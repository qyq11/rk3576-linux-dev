# SN100 上位机移植工程

这是正式移植工作目录；当前仅建立工程约定，尚无业务程序、构建脚本或通过验收的模块。

- 开始任务时先看根目录 README 和 AGENTS，再查 `../../01_docs/plans/sn100_host_migration_plan.md` 的当前模块；目录、规范和参考资料入口见 `../../01_docs/knowledge/sn100_host_project_guide.md`。针对本次模块读取所需源码，不默认加载整份参考工程或所有 Skill。
- 原版位于相邻 `../sn100_host_reference/Seerain450_PC/Seerain450_PC/`。原版代码保持不变；提取本模块及必要依赖到当前工程，记录对应源文件/函数和有意差异，不整包复制 bin、历史数据库、凭据、日志或 `.pro.user`。
- 以 SN100 实际配置和当前 Windows 发行版行为为功能依据；CV450/6600 的同名功能不能直接当作相同协议。原 Windows 基线为 Qt5.14.2/MinGW32；RK候选为当前 Qt5.15.13/AArch64。现阶段沿用 Widgets/qmake，不擅自升级 C++ 标准、Qt 主版本或更换界面框架。
- 修改旧代码沿用邻近文件风格：4空格、Allman花括号以及已有类/对象/信号名称；新接口明确值对象、错误和所有权。QObject父子所有权与智能指针需按实际生命周期选用，不机械套用现代C++模板或全库格式化。新增中文说明采用UTF-8，供应商文件先确认编码。
- 平台差异集中适配；GUI在主线程，网络/定时器遵循对象线程归属；算法不可空实现返回成功。模块未用到的算法、报表等不要求先全部搬入，但受影响链路和必要依赖必须真实可用。
- 按“明确模块输入/原版输出 → 实现 → Windows和WSL ARM64构建 → 离线回放 → RK及现有仪器验证 → 记录 → 下一模块”推进。模拟通过与实物通过分开，保留累计回归；没有仪器参数时不猜旧配置或自动连接。
- 首个业务模块候选为连接和状态/版本显示；先审查全部自动副作用。原状态收包会触发校时/首次收包联动，不能直接接入完整主窗作为只读验证。仪器机械动作仅在该模块已明确的功能范围内执行。
- 编码/调试在Windows，ARM64构建在电脑WSL，产物和日志统一到 `../../temp/sn100_host/`。实际代码开始后才建立 `.pro`、模块目录和符合根约定的 `build.sh`，不创建假构建脚本或提交旧二进制。
- 模块验收保留具体TX/RX或其他真实输入输出、界面/数据库变化、错误/退出码、版本和复测条件。实施证据在同一份 `02_records` 移植记录累计，计划维护状态，敏感信息不进入Git或截图。当前只完成目录和规范准备。
- 每模块保存同等输入/负载下的CPU、RSS/PSS/峰值、线程/队列、日志/存储增长和响应数据；按需核查温度/降频、UI与同板控制任务的竞争。资源预算与实际业务负载对应，优化不能减少必要业务功能、原始采样或异常可观测性。
- 代码删减先验证再正式执行：核对两目标构建/调用链、配置与机型、字符串信号槽、插件/动态加载、资源引用及原版基线；必要时在可撤回副本做禁用或候选补丁对照，通过适用的功能/报文/数据/异常/仪器用例后才纳入正式删减，删后再回归并记录资源变化。引用搜索为空/菜单注释不单独证明无用，不确定就保留；不清理参考原件。
- 实际过程统一追加 `../../02_records/20261022_sn100_host_migration.md`，记录代码删减依据与前后结果、资源测量、失败/复测和回退；Qt安装/版本事实引用既有环境记录，待办仍放计划。
