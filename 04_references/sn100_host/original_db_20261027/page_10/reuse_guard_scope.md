# 高级参数控件复用保护专项检查

本驱动只保存在temp，不修改正式源码或正式114项驱动。由整合窗口交叉编译后直接在RK的EGLFS显示环境运行，电脑不运行产品测试。它沿用正式ProjectPage、正式工作线程和正式原数据库接口，不连接仪器，不运行SQL业务写入，不输出原参数值。

输入必须是已有RK专用原库工作副本，同时带`.sn100-original-work-v1`和`.sn100-original-rk-test-v1`，标记内容与文件名对应且末尾有换行；不能传日常正式工作根。输出目录必须尚不存在，避免导出覆盖上轮资料。调用参数为`--data-dir <专用原工作副本> --output-dir <本次新证据目录>`，输出`reuse_guard.json`。

检查范围：

- 原七项目加载后实际点击PT，核全部高级编辑列与提交快照对应。
- 记录样本表首格QPointer，在只改LIS代码保存读回、明确重读、恢复原代码保存后，核原对象仍存在且仍为当前首格。每次同时比较完整高级UI快照与完整提交快照，避免通过少显示字段来提速。
- 点击原“稀释比例”页并实际修改样本量，先核输入框可见且可编辑；点击取消后核旧对象真正释放、全部高级值恢复、没有残留草稿。原对象名`btnReagentAdd`打开该页，`btnSampleAdd`实际打开不含动作表的“测试方案”页，不能按历史代码名猜页面。Qt延迟释放会通过事件循环和DeferredDelete处理后核对，避免原始地址被分配器复用造成误判。
- 实际点击切换APTT，核旧PT对象释放、APTT全部高级编辑列及已提交快照一致；切回PT核APTT对象释放及全部PT高级值恢复。两项目即使有相同数值，也不靠“它们应该不同”当断言。
- 最后通过正式Store导出完整配置包，保持原目录结构且排除患者/账户库。再正式切换到此导出根，等待真实ready/load信号驱动页面，核同项目同参数也不能跨根复用旧控件，页面和记录都绑定新根。最后切回原根，并核控件重建、值恢复、无草稿。

来源切换与导出使用独立高请求号，放在全部页面写操作之后，不干扰后续页面保存号。此处测试的是正式来源信号到实际页面的处理，不把手动调用Store说成点击了文件选择弹窗。文件选择弹窗操作已由另一份114项驱动覆盖。

此驱动只核正确性，不计算响应达标、物理触屏、原版视觉、长稳或同板控制结论。正式数据不改；专用副本中的LIS代码恢复后才切来源，导出目录由整合窗口在取回证据后处理。
