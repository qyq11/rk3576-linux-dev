# CAN控制器内部回环检查

用途：在RK上逐条显示CAN发送内容及返回的数据来源，分别核对驱动发送确认与接收通道。只能在已断开外部CAN硬件时运行，不代表真实轴卡已通过。

`can_loopback.c`为C源码；`build.sh`接收绝对输出文件路径，生成ARM64程序；`run_loopback.sh`在板端临时设置500000 bit/s普通CAN和控制器回环，结束后停止接口并关闭回环。这个速率不是轴卡正式配置。完整结果统一看[CAN配置记录](../../../02_records/20261102_can.md)：2026-11-02发送确认3帧通过，关闭本机回送后接收超时，不能认定硬件接收通过。

在项目根目录的WSL中编译：

```bash
bash 05_tools/tests/can/build.sh "$PWD/temp/can_20261102/can_loopback"
```

将程序与运行脚本上传至板端同一目录，核对文件指纹及动态库后执行。默认检查3帧本机返回的数据，输出`source=tx-confirmation`只说明驱动确认发送，不能当成接收通道数据。

```bash
bash run_loopback.sh
```

关闭发送确认的本机回送，单独检查是否有数据从接收通道返回：

```bash
bash run_loopback.sh --no-local-echo
```

本轮第二条命令实际退出1，第一帧等待1秒后超时，清理退出0。失败原始日志保留；不要仅凭第一条命令通过就判断排针、收发器或外部接收正常。
