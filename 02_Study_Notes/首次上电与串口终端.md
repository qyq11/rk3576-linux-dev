## 2. 准备哪些工具

- 开发板和匹配的 **5V / 3A Type-C 电源适配器**，或输出规格与供电能力满足官方要求的电源。
- **USB 转 TTL 串口模块**：与板卡调试接口的逻辑电平兼容，并支持 **1500000 波特率**。立创串口教程中提供了其配套工具入口。
- 连接 TX、RX、GND 的杜邦线，接头与实际排针匹配。
- Windows 电脑；串口模块如需独立 USB 数据线，准备可传输数据的线。
- [MobaXterm Home Edition 官方下载页](https://mobaxterm.mobatek.net/download-home-edition.html)，以及串口模块实际芯片对应的驱动。

这一步通过串口观察启动，显示屏、键盘、网线可按需要后续接入。板卡供电与 TTL 串口通信是两条连接，各自按接口用途接线。

## 3. 先在 Windows 确认串口模块能被识别

1. 暂时保持开发板断电，串口模块先不接板卡信号线。
2. 将 USB 转 TTL 模块接电脑。
3. 打开 Windows“设备管理器”→“端口（COM 和 LPT）”，记录新增的 COM 号和设备名称。
4. 如果没有端口，或设备有黄色感叹号，按模块芯片型号安装其官方驱动，再检查一次。
5. 只让一个终端程序占用该 COM 口。COM 号以本机为准，官网示例中的 COM29 不必相同。

原有 RKDevTool、Rockusb 烧录驱动不是这次串口连接的前置条件。不要仅因目录里已有烧录驱动就认为 USB 转 TTL 驱动也已安装。

## 4. 断电接线：按信号名称交叉连接

立创串口教程将调试接口定位为**板卡侧边的三个排针**。先对照官网接线图与实物丝印，确认每针含义，再连接：

| 板卡调试接口 | USB 转 TTL 模块 | 作用 |
| --- | --- | --- |
| GND | GND | 共地 |
| TX / TXD | RX / RXD | 板卡发送，电脑接收 |
| RX / RXD | TX / TXD | 电脑发送，板卡接收 |

按 TX、RX、GND 标签认针，不依据线色、照片左右方向或三针位置猜顺序。用于给外设供电的模块 VCC / 5V / 3V3 引脚不接板卡；板卡由自己的电源适配器供电。模块需为 TTL 串口，不能把 RS-232 电平接口直接接入。

**电平核对边界**：本次读取的串口教程正文没有明确写出三针接口的电压值；接线图与设置图在网页中以图片提供。本记录不预设为 1.8V、3.3V 或 5V。接信号线前，应依据对应版本原理图、官方配套工具说明和模块规格确认兼容；仅看到模块有“3V3”供电脚或电源跳帽，不能据此推断其 TX 输出电平。未确认时可先完成上一节的 Windows 识别。

## 5. 设置 MobaXterm

在 MobaXterm 中选择 `Session` → `Serial`，设置如下：

| 参数 | 初次设置 |
| --- | --- |
| Serial port | 设备管理器中实际的 COM 号 |
| Speed / 波特率 | **1500000**，手动输入 |
| Data bits | 8 |
| Parity | None，无校验 |
| Stop bits | 1 |
| Flow control | None，无流控 |

官方教程正文明确给出 1500000；8N1、无流控作为常规串口的初始设置，实施时还应对照官网 `settings` 截图核对。若下拉框没有 1500000，直接在输入框键入；模块与驱动本身也必须支持该速率。

先打开串口会话，再给开发板上电，这样可以保留从上电开始的日志。

## 6. 怎样接通电源启动

依据官方[电源使用说明](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/development-kit/pa5v3A-tc.html)：

1. 板卡放在干燥、不导电的平面，断电检查接线。
2. 将电源适配器的 Type-C 插头插入板上 **Type-C Power** 供电接口。
3. 将适配器接入交流插座，观察电源指示灯和串口启动输出。
4. 已有可启动系统且供电正常时，按官方快速开始流程接通电源即可启动观察；不需要先在电脑上运行启动命令。

两个 Type-C 接口的用途应按官网供电图和板上标识区分：本次供电使用 `Type-C Power`，不要与 `OTG Type-C` 混淆。官方要求 5V 输入，不使用固定输出 9V、12V 的电源；也不同时通过 Type-C、排针或其他路径给板卡供电。调整板上接线前断电。正常关机后再拔电，等待指示灯熄灭后拆接外设。

官方[供电接口示意图](https://wiki.lckfb.com/storage/images/zh-hans/tspi-3-rk3576/system-usage/index/index_20260507_165346.png)可用于辨认接口位置；仍以实物板版本和标识核对。

## 7. 看到输出后，怎样判断是否能进入终端

| 看到的现象 | 下一步 |
| --- | --- |
| 连续启动日志，随后出现 `login:` | 等系统启动完成，输入当前镜像的用户名和密码 |
| 已出现可输入的 shell 提示符 | 执行系统信息检查命令 |
| 持续打印 Android 相关日志，没有登录提示 | 先保存日志；官方 Android 串口定位主要是实时日志通道，命令交互按其 ADB 教程继续 |
| 停在 Bootloader 提示符 | 记录原始内容；这不是 Linux 用户终端，先核查启动状态 |

立创 Ubuntu24 与 Debian12 串口页面的示例登录信息均为 `lckfb` / `lckfb`。仅在确认是对应的官方镜像、且账号未修改时使用该示例；密码输入时通常不显示字符。当前实物系统尚未确认，不把这些账号视为通用凭据。

官方快速开始说明出厂默认是 Android 14，所以“能看到日志”与“已进入 Linux 登录终端”需要分别确认。如果是首次烧录后的启动，部分官方 Linux 教程提示系统可能自动重启一次。

进入 Linux 用户终端后执行：

```bash
cat /etc/os-release
uname -a
ip addr
ip route
```

保存输出，再继续 [SSH 与固定 IP 配置准备](SSH与固定IP配置准备.md)。若当前为 Android 且没有交互 shell，先按 Android ADB 路线处理，不据此直接刷机。

## 8. 常见现象与排查顺序

| 现象 | 先检查 |
| --- | --- |
| 电脑没有 COM 口 | USB 数据连接、模块驱动、设备管理器状态 |
| 电源灯不亮 | 是否接 Type-C Power、适配器输出和插接状态 |
| 电源灯亮但串口无输出 | COM 是否正确、会话是否已打开、板卡 TX 是否接模块 RX、是否共地，以及信号电平是否兼容 |
| 输出乱码 | 1500000 是否输入正确，模块/驱动是否支持该速率，数据格式及电平是否匹配 |
| 能看到日志但输入没反应 | 板卡 RX 到模块 TX 的接线、流控、是否已进入交互终端；Android 还应核对其串口用途 |
| 反复出现同一段启动日志 | 检查电源与线缆压降，再结合日志判断启动故障；新刷系统的首次初始化重启另行识别 |

本次需要留下的记录：电源标签、串口模块型号及电平设置、板卡接口照片、COM 号、实际终端参数、上电到停止输出或登录界面的日志。取得正式日志时再创建 `04_Test_Records/logs/`；原始照片统一直接放在 `05_Photos/`，不同任务共用该文件夹，按“日期_图片内容_序号”命名。
