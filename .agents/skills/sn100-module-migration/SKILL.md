# SN100 模块开发与验收

目标是交付人能理解和修改、行为可核对、在指定环境实际运行的业务模块。目录漂亮、编译成功、WSL 流畅都不能单独证明 RK3576 稳定或仪器功能通过。

**2026-10-27起按用户要求直接在RK验证：**电脑仅编辑、检查源码、ARM64交叉编译和上传；不再安排Windows/WSL本机运行测试或Windows测试构建。每完成一项功能或修复即在RK核对操作、数据、错误与恢复；RK不可达时登记待RK验证。历史电脑结果保留原范围，原Windows行为/视觉依据使用只读源码、已有截图及用户提供的信息。

## 开始一项任务

以下路径以仓库根为准；先用 `git status --short` 确认已有修改，不覆盖他人工作。

1. 读根 `README.md`、`AGENTS.md`、`06_programs/sn100_host/AGENTS.md`。
2. 读 `01_docs/plans/sn100_host_migration_plan.md` 的“当前需要做”和当前模块卡，以及 `01_docs/knowledge/sn100_host_project_guide.md` 的相关说明；查 `02_records/20261022_sn100_host_migration.md` 已有证据。当前任务/设备状态从这些文件及本次用户指令确定，不把历史候选模块当作当前任务。
3. 编码、重构、性能审查或验收时，读 [业务可读性与运行验收](references/engineering-and-verification.md) 的对应部分；涉及界面还须读其中“原版界面保持与最小适配”并建立视觉对照。创建、移动、改名、删除或归档文件时，再读 `../sn100-project-files/SKILL.md`。

## 先把业务说清楚，再改代码

为当前切片明确“入口/操作者 → 输入 → 校验及业务规则 → 状态或数据变化 → 输出 → 失败与恢复”，找到原版对应函数、必要依赖及有意差异。把这些信息写进当前模块卡/同一移植记录，不另建平行计划。尚未确认的原版行为登记待对照，不自行发明规则。

按实际复杂度组织界面、业务、通信、持久化与平台适配。小模块可以只有入口、页面和数据访问；复杂规则出现后再提取业务对象。不要求为了层数创建空类、通用框架或每类一套接口。改后应能从按钮/消息入口追到最终结果，关键规则有清楚名称和必要的“为什么”注释；详细检查见参考文档。

## 实施与验证

- **界面默认保持原版。** 颜色/主题、布局分组与顺序、控件相对位置和比例、图标/文字及状态含义尽量一致；只做 Linux 与 RK3576 屏幕必需的字体、资源路径、DPI、尺寸和防遮挡适配，逐项记录原因及前后对照。不得因“模块化”“离线演示”“更好看”重画页面、换配色或重排操作；单模块独立运行也遵守原页面基线。具体对照和缺基线处理见参考文档。
- 保持当前 Qt5 / Widgets / qmake 及已选 C++ 标准，旧文件沿用邻近风格；不由外部 Qt6/CMake skill 推导出升级授权。只在正式工作工程修改，从参考工程审查提取所需内容；不运行参考工程或沿用其连接/数据库配置。
- GUI 主线程保持事件循环可处理交互。耗时工作、QObject/SQL 连接的线程归属、队列上限、停止与失败路径按参考文档检查；线程数量、`processEvents()` 或实时优先级不能代替解决阻塞。
- 按“ARM64构建 → 上传核对 → RK实际操作/数据验证 → 适用时接仪器验证”执行并分别登记。原Windows行为与视觉用现有依据核对，不新跑电脑版本；缺少连接参数不猜测、不连接，纯页面模块不安排无关机械动作。
- 需要 RK 构建部署且设备具备时，复用根工作流/现有 Qt 脚本，检查新产物架构、部署 SHA-256、动态库/插件、真实输出和退出码；构建失败不部署旧文件。GUI/长稳时长按任务设置，不能沿用 30 秒就宣称长期稳定。
- 直接在RK用固定输入、数据规模、Release构建和显示条件测功能、操作响应、事件循环延迟与资源，按需核同板控制干扰、温度/降频和目标时长。指标与采样口径先写清；无门槛或无实测时标记待定/待验，不能用主观“顺畅”放行。
- 疑似无用代码按局部 AGENTS 和计划 2.7 节的删前依据、对照和删后回归执行；不确定就保留，不清理参考原件。

## 交付与状态

分别报告：**构建、离线功能、Windows 行为对照、原版视觉一致性、RK 运行/实屏、仪器功能、响应/资源、长稳/同板控制**的已验与待验。功能通过不代替视觉通过；现有演示页不是未经核实就能沿用的新视觉基线。只给有证据的项目打勾；本 skill 本身不构成这些通过结论，也不扩大用户授权。
