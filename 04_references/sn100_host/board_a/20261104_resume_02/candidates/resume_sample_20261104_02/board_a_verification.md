# 板A最小联机核对

本轮由总控统一编译、核指纹、部署和操作板A。作者没有联板或编译；板B不操作。使用板A原七份配置、原资料和原主控，先实读公钥/序列号3bf8222fe1417f6a，核同次主控、默认入口及配置指纹。不要复制旧检查器的固定进程/架号作为新操作许可。

## 只读观察源怎样使用

observer/sample_focus_observer.cpp只观察菜单/登录/草稿确认的显示、隐藏、焦点及按键事件。按正式ARM64 Qt/sysroot构建同目录.pro为共享库，先核AArch64、依赖和SHA；只在当次获准的独立新程序进程设置LD_PRELOAD为该库的实际绝对路径。设置SN100_SAMPLE_FOCUS_OBSERVER_OUTPUT为板A已创建的独立目录/home/rkshare/programs/sn100_shell/verification/resume_sample_20261104_02/下一个新的.jsonl文件。文件不存在才写入，路径错误或无法打开只停用观察，绝不退出或接管产品。

观察器使用Qt启动回调安排观察，不拦截QCoreApplication::exec；这是比旧button_audit更窄的只读方式。没有自动登录、点击、取消、关闭、发送设备命令或退出调用。日志不写账号、密码、编辑文本、样本号或任意按钮文字。满5分钟或4000条只停止观察，不关闭应用。写日志会增加少量主线程工作，本轮结果不能作为资源或响应门槛通过。

## 操作和判定

1. 用户正常完成登录。先在样本总览新增本轮普通空架，记下本轮实际架标识；不要按旧S01/S02或旧id定位。再双击新架进入设置。确认输入窗口确实是本次新程序。
2. 点击第一孔容器下拉框，先不选项目、不保存或开始检测。观察两项“试管/生化杯”是否持续可见；分别用鼠标选择一次、重新打开后点菜单外、重新打开后按Esc。每次确认菜单结束后其他普通按钮仍能操作；外点和Esc只关菜单，不能改变原容器值或退出样本页。记录实屏和实体输入结果。
3. 在本轮空架切换容器形成未保存草稿，确认后端原架仍为原默认值。点加号：应先在后端新增另一普通空架，再出现旧草稿确认。点“取消”，新增架必须保留，仍停在原架，原容器草稿也保留；不能为通过检查改为自动放弃。
4. 在该原架点返回，再选择“放弃”。只能丢弃本轮容器草稿，两个已新增空架都应保留，回到总览。重新进入原架，容器恢复后端原默认值。没有“放弃”时不应提前写库或改默认。
5. 对照观察文件：widget_event中Show/FocusOut/Hide的顺序、focus_reason；window_state中popup是否存在但visible=false，以及focus、mouse_grabber、keyboard_grabber、modal。普通菜单关闭后不应留下当前容器的不可见activePopupWidget。菜单未显示、输入无响应或其他弹窗出现时先收证，不能自动清架、强关或调整超时当作通过。
6. 仅在确认是本轮所建且始终为空、未被别人使用的架时，由总控按用户当前授权决定是否清理；不能无条件按架名删除。应用通过正常关闭流程结束，回读真实退出码、线程清理、原主控与七配置。退出遇到登录窗口按现有保护处理，不修改账户/公共离页逻辑。

原失败result.json仍保留9通过/1超时。需分别登记：菜单是否可用、取消/放弃是否符合原版、实体输入/实屏、配置/主控、正常退出。没有执行这些步骤不能把候选称为修复通过。若仍整页无响应，已确定的菜单焦点冲突与现场整页故障继续分开记录，不把全部原因归给它。
