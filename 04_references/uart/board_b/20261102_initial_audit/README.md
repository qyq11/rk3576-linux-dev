## 配置前还要注意的实际缺口

- 当前`/dev/ttyS4`权限为`root:dialout`、`0660`，本次`lckfb`会话不在`dialout`组。后续需要让运行程序的普通用户取得串口访问权限，并在重新登录后核对；本轮没有修改用户组或设备权限。
- 两组RS485需要确认由转换电路自动切换收发，还是由额外信号控制。源码中，UART3 M0的`RTS`信号位于18脚，与图中的急诊指示灯重叠；UART8 M1的`RTS`位于28脚，与UART7发送信号重叠。`RTS`可被某些方案用于控制发送方向，不能未经电路核对就加入这两组引脚。
- 图中只安排串口的TX/RX，即发送/接收两根信号，没有安排硬件流控线。若后续启用流控，UART4的CTS/RTS还会用到13、32脚，UART9的CTS/RTS会用到36、22脚，与图中的灯光安排重叠；先按设备资料核清是否需要。
- I²C7、I²C8和SPI1第二片选确有内核占用，外接设备和业务用途还没有核实。本轮没有扫描这些总线，也没有查询外设，不能据此认定它们可以直接停用。
- 各外设的波特率、校验、报文和电气转换/接线仍需实际设备资料。本轮没有用`stty`或程序打开串口查询参数，以免打开动作改变串口控制信号。
