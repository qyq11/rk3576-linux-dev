# SN100 工程文件管理

文件组织服务于业务阅读、构建和复现；不为目录整齐打断现有开发，不预建空架构。以下均以仓库根为基准。

本项目自2026-10-27起，源码/资源变动后的功能、界面、保存重开及资源验证直接在RK执行；电脑只做源码检查、ARM64交叉编译和上传，不再安排Windows/WSL本机运行测试或Windows测试构建。历史目录和证据保留原范围，不因验证方式改变清理旧文件；RK不可达时登记待RK验证。

## 先确认范围

读根 `README.md`、`AGENTS.md`、`06_programs/sn100_host/AGENTS.md`、当前移植计划与工程管理说明。先看 `git status --short` 和相关差异，再用 `rg --files` / `git ls-files` 盘点本次对象；区分已跟踪、已有未提交、被忽略、唯一原件和可重建文件。不默认遍历/复制参考包的生产数据库或凭据内容。

## 文件归属与唯一维护位置

| 内容 | 正式位置与管理方式 |
| --- | --- |
| 程序入口/源码/构建 | `06_programs/sn100_host/`：入口保持简短；`.pro/.pri`、真实构建/启动脚本同属源码；按业务需要放 `ui/`、`data/` 等，复杂度达到时再加业务/协议目录 |
| UI 与资源 | `.ui` 和页面代码放对应业务位置；必要图标/QSS/翻译/QRC按实际创建资源目录，文件名表达用途；保留原主题/图标/共享样式及加载关联，不以整理名义换皮肤，不与生成的 `ui_*.h` 混放 |
| 测试源码/匿名夹具 | 程序内 `tests/` 随实际测试创建；小型固定输入/金样本可放 `tests/fixtures/` 并入 Git，说明字段、来源、期望和是否匿名化；不把测试的可变运行库当夹具 |
| 独立接口测试 | `05_tools/tests/<interface>/`；不把程序内部业务单测搬成全局接口工具 |
| 第三方源码 | 模块确需且可分发时再引入独立位置，注明版本/来源/许可/本地补丁，避免自行修改后伪装成原件；安装/恢复输入另走正式归档 |
| 构建/缓存/临时运行数据 | `temp/sn100_host/`：按 Windows / WSL x86_64 / RK ARM64 及 Qt版本、Debug/Release 隔离，日志、回放输出和可变离线数据库再分开。以现有脚本实际路径为准，不只为命名统一移动正在用的构建树 |
| 目标运行数据 | 程序显式指定的可写数据根，与只读安装资源区分；配置、DB、日志、导出各有边界。使用参数或合适的 Qt 路径 API，不依赖 IDE 当前工作目录，不读取参考包历史生产库/旧连接配置 |
| 原版与压缩原件 | `06_programs/sn100_host_reference/` 只读参考、本地保留；不构建、不清理，不整包强制加入 Git |
| 环境安装/恢复输入与必要备份 | `07_backups/<事项>/`：来源/版本/恢复范围/SHA-256 随 Git；镜像/压缩备份按已有规则用 Git LFS，出现新扩展先核查属性，不只放在 temp |
| 计划/知识/过程 | `01_docs/plans/sn100_host_migration_plan.md` / `01_docs/knowledge/sn100_host_project_guide.md` / `02_records/20261022_sn100_host_migration.md` 各自唯一维护，不增平行日志或每模块 README |
| 证据/图片/技能 | 长期非认证敏感证据放 `04_references/sn100_host/`；原图与标注放 `03_photos/`；本项目技能放 `.agents/skills/`，不放 temp 或个人全局目录 |

当前脚本若采用 `wsl_release`、`wsl_tests`、`runtime`、`logs`，可继续使用；新增其他架构/配置必须明确分开。不同架构不共享对象、moc、uic、Makefile 或库搜索路径。现有计划中的路径示例不自动构成重命名任务。`06_programs/sn100_host/data/` 当前保存数据访问源码，不能按目录名把它当运行数据清理；临时目录中的 sysroot/唯一依赖也不能仅因位于 temp 就删除。

## 创建、移动、改名与删除

1. **先说明用途与受影响范围。** 有移动/改名时记录“旧路径 → 新路径”、原因及回退方式。简单、可搜索的英文文件名，围绕实际业务；不批量改已有类名/objectName，不按扩展名随意重排 Qt 工程。新增目录必须有实际内容。
2. **移动前建立引用依据。** 查 `.pro/.pri` 的 SOURCES/HEADERS/FORMS/RESOURCES/TRANSLATIONS/INCLUDEPATH/LIBS/INSTALLS/DISTFILES、include、QRC前缀/alias、QSS/图标路径、翻译上下文、自动槽/字符串信号槽、插件与动态加载、运行配置、脚本、文档链接；核对 Linux 大小写。Windows 上仅大小写改名用临时中间名处理，再确认 Git 记录。
3. **备份按实际写入决定。** 可重建产物不额外备份；覆盖或迁移不可重建数据/配置时只保留恢复必需部分，放正式归档并注明恢复边界。不复制密码、私钥、真实患者数据或认证凭据。原件/用途不明文件不删。
4. **实施只改已授权范围。** 不运行“大扫除”或全库格式化；未提交文件也可能是唯一工作成果。清理可重建内容前确认没有正在使用它的构建/运行进程、没有唯一源码或证据，实际绝对目标在本项目预期目录内；不通过跨 shell 拼接字符串批量删除。
5. **同步并验证。** 更新引用与 README/同一记录；移动源码/资源后做受影响目标的干净构建，并验证资源加载、业务行为和数据重开。缺目标环境则记录待验，不能称整体完成。纯说明/skill 修改检查引用与结构即可，不触发无关编译、设备连接或环境安装。

代码“是否无用”不是文件归类问题，需执行局部 AGENTS / 计划 2.7 节的删前对照和删后回归；没有证据不能借整理名义删除业务代码。

## Git 与交付核查

- Git 跟踪正式源码/构建/skill/文档/必要匿名夹具，不提交对象、moc/uic、个人 `.pro.user`、可变运行库、临时日志或部署凭据。不要新增全局 `*.db`、`*.json` 等规则把有效夹具和清单一起隐藏；忽略规则优先限定生成目录。
- 对新归档或夹具用 `git check-ignore -v <具体文件>` 核对；对镜像/压缩包用 `git check-attr filter diff merge -- <具体文件>` 核对 LFS，来源与校验清单仍可读。`.gitignore` 不会取消已跟踪文件，发现误跟踪时先核查用途，不直接删工作副本。
- 完成后给出本次新增/移动/删除、引用/构建/运行实际核查结果和待验范围，统一追加同一移植记录；更新必要入口。保持用户已有修改，不自动提交或推送。
