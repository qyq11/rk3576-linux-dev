# 留屏观察接口：总控裁定v1

2026-11-03。依据状态/登录窗口的`20261103_lis_keep_running_candidate_01/runtime_contract_proposal.md`及构建窗口的`workflow_next_20261103/build_archive_candidate_01/operation_contract.md`。此裁定只授权新独立候选的源码/模板实现，不授权作者构建、联板、切版或操作当前程序。

## 程序与观察身份

1. 采用一个业务程序进程。新的被动观察CPP拟随下一版正式程序链接，普通启动缺少观察参数时不创建观察定时器、不写结果、不改变业务。具体正式文件和build接线仅由root在源审通过后处理；当前程序不装载、不附加、不注入，也不启动第二个同板界面。不保留旧自动检查CPP的注册或退出逻辑。
2. 不使用编译宏预填未来实际release_id。当前发布号由包内SHA256SUMS计算，而主程序又在清单内；若二进制包含这个发布号，会形成循环依赖。发布号由root核包之后在新进程启动时传入，候选先保持未知；采集器再与实际current、release_id文件、程序路径和SHA交叉核对。环境中收到的预期SHA不得标为程序已独立实测的SHA。
3. 保留`SN100_LIS_OBSERVATION_DIR`、`SN100_LIS_OBSERVATION_ID`，增加运行时`SN100_LIS_OBSERVATION_RELEASE`。根目录由root预建私有新目录，不覆盖；参数缺失、格式不符和写入失败不得结束业务程序。具体参数值只由root在真实新版本到齐后提供。

## 观察与结果

- GUI线程只读实际LIS对象、已提交配置的来源/版本、顶部控件的唯一性/实际类型/结构提示和连接状态。只观察受影响项，不重跑登录/注销、主通信断开、Qk、机械动作或旧26项。只断开观察器自己的订阅，不调用`control->close()`或任何业务停止方法。
- 最多等就绪60秒，再有限观察15秒；记录实际时长。所有成功、失败和超时路径停止自己的定时器，保存实际快照或失败原因，窗口和主通信继续运行。就绪不足不填软件通过；无真实对端不记真实LIS连接/业务通过。
- 不在GUI线程对大可执行文件或整个包做SHA。CPP记录实际PID、start_ticks及窗口状态；实际exe/current/包和SHA由外部采集器在读取前后校验。JSON本身的SHA及一次小快照写入可在此边界实现，并明确写失败。
- 按草案先原子保存`lis_observation.json`，再原子保存`lis_observation.ready`，完成标记绑定观察ID、实际传入发布号、PID和JSON SHA。结果schema沿`sn100-lis-keep-running-observation-v1`。
- 明确：`observation_complete`是快照封口，`application_exit=null`，`application_exit_evaluated/shutdown_evaluated/close_verified=false`。实际检查数组和failed数只统计本次已评估项，未执行项另列pending。
- 只保留白名单的来源摘要、配置版本/连接代次、对端数、状态、控件定位和错误摘要，不保存INI正文、密码、患者/任务/报告、自由消息正文或传输内容。不为通用脱敏破坏证明所需字段；计数或来源标识不能误报为已验证认证内容。

## 启动、被动等待与采集

- root负责唯一的实际启动编排。状态窗口的等待器不启动/关闭应用，构建窗口的切换模板不声称已经通过留屏验证。保持各自边界，不再新增相互冲突的runner。
- root安排必要版本切换时，先完成新包暂存和归档，再串行处理旧程序、指针与新启动。正式程序运行时的只保存阶段使用独立不可变存储锁，不碰current；切换采用约定锁顺序和真实旧进程检查。原主控不重复启动。
- 不直接把旧`rk_board.sh start 0`当成不关闭的监督：其就绪等待超时仍会TERM。优先评估复用既有`supervise ... 0`和独立只读就绪等待；若发现子监督器其他停止路径须如实列，不为拿锁或超时清理而结束应用。root最终审定实际启动脚本。
- 等待器采用自身截止时间返回，不向产品发TERM/KILL。超时、采集失败或软件观察失败只记录本工具真实退出。内部观察模块没有单独进程退出，字段不得把它和应用混淆；如需工具退出字段，使用`waiter_actual_exit`/`parser_actual_exit`。
- 接受草案的板序列、SSH固定指纹、boot、PID、start_ticks、exe路径/SHA、current/发布/观察ID的前后双核及两份身份记录。窗口存在/可见加前后同一活进程只证明这段观察，不能替代实屏或未来长稳。
- 只采两份已封口结果、两份实际身份和采集状态/清单。持续app.log和resources不作前后相同要求。采集成功、软件观察结果、真实LIS业务和应用仍运行分别判定，不用一个0替代其他结论。
