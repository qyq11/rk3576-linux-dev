## 目标与资源依据

资源分配以[40Pin 工程资源分配表](../../04_references/RK3576_40Pin工程资源分配表.jpg)为规划依据；实施前核对实际板卡、电平、引脚复用、设备节点和占用情况。图中的主功能、复用功能是候选选择，不能默认同时启用。

- **扩展 TTL 串口：**通过 CH340 等 USB 转 TTL 模块，与 Windows 做实际的双向数据收发。
- **GPIO 输出：**控制单个引脚的高、低电平，用万用表在实物上测量。
- **GPIO 输入：**外部改变单个引脚电平，程序捕获变化并打印当前状态。
- **CAN 回环：**保留，独立验证 CAN 控制器对应的收发路径。
- **后续系统工作：**PREEMPT_RT 实时补丁、Samba 文件共享。
- **后续资源扩展：**根据图中备注推测 PWM、SPI、I²C 用途，具体外设和优先级在实施前确认。

**所有实验都要让人看到并核对实际结果。** 先明确测试输入、预期输出和核对方法；无法观察结果的方案先调整，不安排执行。通信和回环必须显示实际发送、接收的具体数据，并标明设备、方向和序号；GPIO 等实验显示实际电平变化、实物现象或测量结果。只输出字节数、匹配数量、Result 或 PASS/FAIL 的回环任务不再做，统计仅作为实际内容之后的汇总。示例日志是验收目标，不代表已经执行。

**板端程序约定：**上传到 RK 并运行的程序使用 C，不使用 Python；默认优先用 GCC 编译，可在 RK 上原生编译，或使用匹配 AArch64 Linux 的 GCC 交叉工具链。交付时给出源码、编译、上传和运行命令；新版本的编译与硬件验证单独确认，保留历史实测证据。

## 当前推进

### 1. 扩展 TTL 串口，与 Windows 实际收发

- [ ] 按资源表确认并启用所需 UART，记录引脚、电平、Linux 设备节点和 Windows COM 号。

| 规划接口 | TX 物理针号 | RX 物理针号 | 复用关系 |
| --- | --- | --- | --- |
| UART3 M0 | 5 | 3 | 与 I²C7 共用引脚 |
| UART4 M0 | 8 | 10 | 已确认 /dev/ttyS4，待做 Windows 实际收发 |
| UART7 M0 | 28 | 27 | 与 I²C8 共用引脚 |
| UART8 M1 | 37 | 40 | 实际启用状态和设备节点待核对 |
| UART9 M0 | 26 | 29 | 26 针也可作为 SPI1 第二片选 |

- [ ] **Windows 发 → RK3576 收**：CH340 TX 接目标 UART RX，双方共地。Windows 发送带方向、序号的已知数据，例如 PC_TO_RK_0001；RK 程序明确打印“UART4 RX：PC_TO_RK_0001”，核对内容和数量。
- [ ] **RK3576 发 → Windows 收**：目标 UART TX 接 CH340 RX。RK 发送 RK_TO_PC_0001，并打印发送内容；Windows 接收区实际出现同一数据，核对内容和数量。
- [ ] 每一路先完成单条可见收发，再验证连续编号数据，保存两端的实际内容、数量和异常；重启后按同一配置复测所需接口。

**完成标准：**所需各路两个方向都能看到并核对真实数据，参数、接线和设备对应清楚。Windows 的本地发送显示、终端回显不单独作为接收成功依据。

测试时移除目标 UART 的 TX—RX 回环短接线，再接 CH340；确认信号电平兼容，模块电源脚不接独立供电的板卡。若只有一个 CH340，将其用于被测 UART，板端操作改走已验证的有线 SSH；调试口与业务测试口分别管理。

### 2. 单引脚 GPIO 输出：高低电平与万用表实测

- [ ] 按图确认 LED-R（13）、LED-G（15）、LED-B（16）、LED-E（18）、LED-P（22）、LED-D（36）、Run（38）等输出规划；括号为物理针号。
- [ ] 每次先测试一个引脚，确认 GPIO 映射、输出方向及高低有效关系，通过当前系统可用的 GPIO 接口分别保持高电平、低电平。
- [ ] 程序打印具体引脚及输出设定；万用表相对 GND 测量并记录实际高、低电压。接有 LED 时同时观察亮灭与电平的对应关系。

**完成标准：**命令或程序的设定、打印信息和万用表实测一致。软件读回值不能替代引脚电压测量；高电平电压按实际 IO 电源域确认，不预设为 5V。

### 3. 单引脚 GPIO 输入：外部电平变化触发打印

- [ ] 按图确认 K1（33）、K2（31）、K3（32）的输入规划、上下拉及有效极性。
- [ ] 用兼容的外部高、低电平或按键改变输入，先读取初始状态，再捕获 0→1、1→0 的变化。
- [ ] 程序通过 GPIO 边沿事件等待变化，打印引脚、时间、当前 0/1 状态及变化方向，例如“GPIO_IN K1：0→1”。有按键时验证消抖和重复触发情况。

**完成标准：**外部每次受控变化都能与打印结果对应，能够区分高、低及变化方向；单独看到程序启动或 PASS 不算完成。

**文件接口的准确含义：**GPIO 的 value 等是内核提供的虚拟接口，不是普通文本文件被重写。若本机采用 sysfs，检查支持情况后配置 edge，用 poll 等等待事件并重新读取 value；新程序也可通过 /dev/gpiochipN 和 libgpiod 读取边沿事件。实现方式按现有系统和工程约束确定，不按普通文件的修改时间或 inotify 事件来设计输入捕获。参见 [Linux 6.1 GPIO sysfs](https://www.kernel.org/doc/html/v6.1/admin-guide/gpio/sysfs.html)、[GPIO 边沿事件接口](https://docs.kernel.org/userspace-api/gpio/gpio-v2-line-event-read.html)。

### 4. CAN 回环测试（保留）

### 5. PREEMPT_RT 实时补丁与验证

- [ ] 确认当前 Rockchip 厂商内核的源码版本、配置和可匹配的 PREEMPT_RT 补丁；将必要的编译、部署环境准备纳入本事项。
- [ ] 完成补丁适配、实时配置、构建和部署，保留可恢复的原内核；启动后确认实时配置实际生效。
- [ ] 在相同负载下比较普通内核与实时内核的时延，记录工具输出、测试条件和最坏时延；需要验证 GPIO 输入响应时，区分内核事件时间与用户程序打印时间。

**完成标准：**实时内核能稳定启动，提供配置生效和时延对比的实际证据。具体响应期限在测试前确认，不以“补丁应用成功”或终端打印快慢直接判定实时性达标。[PREEMPT_RT 依据](https://docs.kernel.org/core-api/real-time/index.html)。

## 后续扩展：根据资源表推测，外设尚待确认

以下是根据引脚名称和复用备注推测的工作方向，不视为已经确认的器件或已经启用的功能。

### 7. PWM 输出、调光与蜂鸣器驱动

- [ ] **推测用途：**独立 PWM 波形输出、LED 调光，以及在蜂鸣器为无源器件时用 PWM 驱动发声。实际用途要结合外部电路和器件类型确认。
- [ ] 核对图中的候选资源：12 针 PWM1_CH1_M0、22 针 PWM2_CH6_M2、32 针 PWM0_CH1_M2、33 针 PWM2_CH6_M0、35 针 PWM1_CH5_M0、36 针 PWM2_CH7_M2。
- [ ] 按所选用途启用对应 PWM 通道，通过系统提供的 PWM 接口设置周期、占空比和使能状态，打印实际配置。
- [ ] 用示波器或逻辑分析仪测量频率、占空比；接好已确认的负载后观察调光、发声等效果。

**完成标准：**设定值、波形实测和负载表现能够对应。万用表直流读数可辅助观察平均电压，不能单独证明 PWM 频率和占空比。[PWM 接口依据](https://www.kernel.org/doc/html/v6.1/driver-api/pwm.html)。

**复用约束：**22、36 针与 LED GPIO 规划互斥；32、33 针与 K3、K1 输入规划互斥；35 针需区分 GPIO 开关型蜂鸣器和 PWM 驱动。图中 22、33 针都标为 PWM2_CH6 的不同复用方式，应先按同一通道的候选引出方式核对，不能当成两路独立 PWM 分配。

### 8. SPI1 外设数据读写与片选验证

- [ ] **推测用途：**SPI 外设通信，例如读取传感器/ADC/存储器数据或发送控制命令；具体外设、协议和测试数据在实施前确认。
- [ ] 按图核对 19 针 MOSI、21 针 MISO、23 针 CLK、24 针 CS0；26 针是候选 CS1，与 UART9 TX 互斥。
- [ ] 确认外设驱动或实际 spidev 节点，配置时钟、模式、位宽和片选；打印发送命令及接收的原始字节、寄存器值或器件 ID。
- [ ] 如需要一条总线接多个器件，分别验证片选只选中预期器件，再做各器件读写。

**完成标准：**接入明确的外设，返回值能按器件协议核对；只生成设备节点或程序返回成功不作为读写验收。[SPI 用户接口依据](https://www.kernel.org/doc/html/v6.1/spi/spidev.html)。

### 9. I²C 外设寄存器访问（按图补充的推测）

- [ ] **推测用途：**通过 I²C 接入传感器或其他低速器件，读取已知寄存器或发送配置。
- [ ] 图中 I²C7 使用 3 针 SDA、5 针 SCL，与 UART3 互斥；I²C8 的候选复用使用 27 针 SDA、28 针 SCL，与 UART7 互斥。
- [ ] 确认外设型号、地址、上拉与电平、实际总线节点，打印地址、寄存器、写入值和读回值。

**完成标准：**所选外设的已知数据或配置读写能按资料验证。仅列出总线节点或扫描到地址不替代功能验证。
