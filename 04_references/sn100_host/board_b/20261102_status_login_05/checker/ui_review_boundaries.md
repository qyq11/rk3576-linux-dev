## 角色 0 与未认证访客必须分清

当前权限链没有把“Guest 文字”直接当成未登录：

- `data/account_store.cpp:530–540`：空口令按原配置建立 `name=Guest`、`role=0`、`authenticated=true`、`source=Configured`，同时加载原角色字典的授权。它是明确配置的已认证身份。
- `instrument/instrument_page.cpp:39–44`：有原策略来源且来源为 Password 或 Configured 时，角色 0 也可以登记本地人工维护。因此不能断言 Configured Guest 的全部维护按钮都禁用。
- `instrument/instrument_page.cpp:476–483`：端口、功能和通信入口要求管理员；板卡状态要求至少角色 4。Configured role 0 不满足这些门槛，四入口隐藏符合当前源码。
- `data/account_store.cpp:420–432`：实际注销后清成默认未认证会话；原策略来源和角色标签可以保留，但不等于已认证。现检查器的四入口隐藏断言发生在注销之后，仍然合法。
- `shell/frmmain.cpp:465–532`：仪器主页导航本身没有管理员身份门槛，未认证访客可以进入状态页。不能把“访客可看仪器状态”误报成权限漏洞，也不能把“管理员有仪器状态/维护”误写成这两个页面只许管理员看。

自动段可以分别记录“Configured role 0”与“已注销未认证”两种真实会话；不能直接调用设置会话或改角色来制造管理员通过。

## 必须另记的人工界面操作

后续在协调方指定的同一第 05 轮正式程序、原资料和真实主控上，由使用者输入既有账户密码。不得读取、重设或保存凭据，不在人工输入密码阶段截图或录屏。自动检查的原 Guest 页面截图不能替代该人工步骤。

需要人工确认的项目包括：

1. 启动时登录卡确实出现在当前屏幕内，文字、输入框和按钮不被裁切；用现场键盘/触摸或鼠标能输入和点击。
2. 用现场操作关闭登录卡，观察不会自行反复弹出；点头像再次打开。界面没有可见取消入口时，应按实际可见关闭方式记录，不把程序调用 `reject()` 写成人工取消。
3. 用既有管理员账户和密码登录，核屏幕显示的身份、仪器操作中的端口/状态/维护等实际入口；只浏览已获准页面，不点击功能测试、通信测试或维护动作按钮。
4. 点真实注销入口，核身份清除、登录卡重新可输入，再用既有普通账户与管理员账户分别登录，按原角色规则比较入口。没有对应账户或密码时标待验，不能临时造账户代替。
5. 看左上角状态在机型下方实际可见；等待连接时灰灯有完整明暗往返，启动 GIF 在启动阶段实际播放。需要动态短片或现场观察，单张图不够。
6. 只有真实主控自然处于正常测试分支时才核绿色闪动。`shell/device_status_shell.cpp:64–100` 按实际主状态和灯状态联合选图：例如灯状态 1、主状态 5 才是该分支的测试闪动；异常、暂停和试剂不足有各自颜色。不能把“已连接”一律改成绿闪，更不能注入状态假装测试。
7. 人工从真实导航进入仪器状态、端口和维护页，只查看已上报数值及原页面；保留未上报/未确认提示，不把页面能打开当成数值和设备动作已经全部通过。

上述人工登录若在联机条件满足时触发原有资料同步，需要按实际 TX/RX 单独登记；不能沿用自动段断开 TCP 后登录得到的“监听区间只有 Qj”结论。`shell/device_control_shell.cpp:306–354` 会在认证、实际状态及资料条件满足时启动原同步，这属于正常业务链，不能为了测试静默而改会话、同步完成标记或状态。
