# 项目默认校准参数候选交接

本片让使用者在原“项目设置→校准参数”页维护以后新建校准任务采用的六项默认设置。沿用原下拉、页面位置、保存和取消入口；不执行拟合，也不修改已有校准曲线。原字段、初值和调用链见`source_audit.md`。

改动仅在本目录`candidate/`；正式源码、`main/build`及共用计划均未修改。底稿来自开始本片时的正式工程，`base_manifest.json`记录六份底稿的指纹，包含已合入的保存前自动备份。`existing_project_repository_changes.patch`只是当时已有仓库修改的旁证，不是本片补丁。

## 用户怎样操作

1. 在当前原库模式选择项目，进入原“校准参数”页。已有本地`catalog.db`模式不新增未经原版核对的编辑入口。
2. 在现有编辑权限允许时，从原下拉选择稀释方式、重复次数、方法、点数和两种坐标变换。“自动稀释”隐藏手动点数但保留其值。
3. 点原“保存”按钮，等后台回执后重新读取；未保存的输入不进入任务默认值。点“取消”恢复已提交快照。切项目或离页仍走当前未保存修改提示。
4. 原键缺失的项留空并禁用，不自动新增。未知旧值显示原文；未动它就原样保留，改动后只接受原下拉列表。保存失败保留草稿；库已被外部修改则拒绝覆盖，需重新读取核对。

候选沿用当前工程已有权限规则，未更改角色或运行态条件。原局部页面角色判断和父窗口状态边界单列核查，不把它混进本片参数编辑。

## 窄改动

本片补丁只应包含以下三个目标；其余三份候选副本仅保证对象编译时头文件和值对象布局一致，不作为覆盖正式文件的输入。

- `projects/projects_store.h`：为原项目增加六项默认值草稿。`ProjectRecord`是既有跨线程值对象，没有新增线程、请求或信号。
- `projects/project_page.cpp`：恢复原校准页按钮，填入六控件，按现有权限控制编辑，保存时收集已有键，取消仍重建原快照。`.ui`和样式不变。
- `projects/original_project_repository.cpp`：读取六项原键，拒绝增删键和不在原列表内的新值，只把改动项合入既有事务。完整原参数快照仍只读，旧文件指纹与备份核验保留。

必须应用窄补丁，不复制整份候选公共文件覆盖后来修改。`ProjectRecord`布局变动要求后续完整程序重新编译；本目录对象检查不能替代总协调的完整构建和链接。

## 必要差异和待验

原未知值可能被下拉首项覆盖，缺键可能显示前一项目的值。本候选保留未知原串、缺键不显示残留值，均已在原调用链说明；没有追加新方法、拟合条件或默认数值。原浓度启用框的点击联动保留，未据加载时勾选状态添加新的保存拒绝。

原有显示残留也明确保留：点击关闭浓度计算后再取消或切项目，校准区父容器可能仍灰显。原加载同样不重设该父容器；本片不以恢复参数编辑为由静默修原规则，待RK核对后由总协调另定。

独立只读复核已检查三份改动文件的键集合、原选项、未知/缺失值、取消及失败草稿、自动备份和事务，未发现新增确定持久化问题。另核原主窗口导航及全局触控过滤，没有找到检测状态额外挡项目保存的源码链；当前工程的既有运行态守卫仍保持不变。完整已核位置与证据边界在`source_audit.md`。

本片仅准备后续批次候选，不进入当前03正式快照。只做源码核查和ARM64对象编译；不运行Windows/WSL产品，不访问实际或模拟端，不连接RK。功能、保存重开、取消/失败/权限切换、原界面实屏及资源响应均待总协调在获准的RK原配置条件下核对，不能把对象编译通过说成业务通过。
