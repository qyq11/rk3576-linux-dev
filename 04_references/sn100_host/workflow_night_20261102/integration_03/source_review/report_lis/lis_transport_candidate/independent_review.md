# 候选独立源码复查

两名子Agent分别只读核编码/分帧，以及原通信生命周期和候选重入路径；没有运行程序、服务、模拟或回环，也没有给出Windows/RK/仪器通过结论。修改由本窗口实施。

已根据复查修正：

- 断开连接时，先完成发送队列的目标移除，再发结果通知，避免通知槽立即stop/configure导致旧索引越界。
- 广播先无信号登记所有目标的在途状态，再逐个写入；首个目标回调停止时，剩余目标仍能回报NotSent。
- 旧连接通知后核代次，防止旧错误重启新会话的重连计时器；接收交付、调度阶段和监听失败都保留正确代次。
- 停止期间禁止configure/open；更换配置前先清旧令牌，退出时先撤armed和计时器。
- 连接期限与重连使用PreciseTimer，写入期限按实际elapsed观察；不把QTimer当硬实时保证。

编码复查核了完整帧与半帧共存、空帧、跨读取的UTF16头尾、同批超限不发布；未发现需要修正的确定编解码缺陷。奇数UTF16拒绝与原版截断不同，已在交接中单列。原版按字节搜尾的风险保留，没有另造正文转义。

上述首轮编码复查漏了Qt5的UTF8重载差异。总窗口随后指出NUL正文转换不一致；复查者重新只读核原`liscommsetting.cpp:248`、实际编译Qt5.15.13的`qstring.h:711–712`和`qbytearray.h:76–83`，确认恢复`QString::fromUtf8(body)`正确，原始正文不会被截断。候选现仅修正该调用与原因注释。本轮结论只来自源码，没有运行Windows/WSL报文测试、服务或RK程序。

最终三处窄接线复查确认：loaded/saved只有configure，closed/aboutToQuit停止，没有openConfirmed调用；link只进入令牌/response_mode日志，不做TCP开关；构建sources及headers在数组声明之后追加，moc会扫描传输头；qmake路径与已有QtNetwork依赖正确；报告渲染辅助程序未引入LIS。

本窗口随后补了明确的未处理入站socket关闭及待接受连接上限，再经生命周期复查者只读核对：设置上限在listen前，stop先禁止新动作再清旧pending，accept通知后检查代次，未发现确定问题。待接受队列16与已接入对端16是各自上限，不能说整个进程只有16个socket。最终代码包含在指纹和对象重编范围内，没有因此宣称运行、资源或错误恢复实测通过。
