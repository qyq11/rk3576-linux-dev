- 最初输入 `ip link show end`，提示设备不存在；后续补全为 `end0`，命令正常。该提示来自接口名称少了末尾数字 `0`，不能据此判断网卡故障。

照片中 `ip link show end0` 的关键信息：

```text
3: end0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP mode DEFAULT group default qlen 1000
    link/ether 3e:c3:c5:4e:c4:22 brd ff:ff:ff:ff:ff:ff
```

| 项目 | 含义 |
| --- | --- |
| `3` | Linux 网络接口索引 |
| `UP` | 管理状态已启用 |
| `LOWER_UP` / `state UP` | 驱动报告链路已建立，接口处于可传输的运行状态 |
| `BROADCAST` / `MULTICAST` | 支持广播及组播 |
| `mtu 1500` | 接口最大传输单元为 1500 字节，不是链路速度 |
| `qdisc mq` | 使用多队列排队规则 |
| `qlen 1000` | 发送队列长度参数 |
| `link/ether 3e:c3:c5:4e:c4:22` | 有线接口 MAC 地址 |
| `brd ff:ff:ff:ff:ff:ff` | 以太网广播 MAC 地址 |

最新的 `ip -br addr` 显示 `end0` 为 UP，地址为 `fe80::3cc3:c5ff:fe4e:c422/64`；仍未显示 IPv4。该地址是 IPv6 链路本地地址，与计划配置的 IPv4 固定地址不同。

`nmcli device status` 先显示 `end0 ethernet disconnected --`，稍后显示：

```text
end0  ethernet  connecting (getting IP configuration)  netplan-end0
```

因此已确认 NetworkManager 正在管理 `end0`，当时正使用 `netplan-end0` 连接获取 IP 配置。结合直连环境和未出现 IPv4，可能是自动地址获取尚未成功；具体 IPv4 方法仍以连接属性为准。物理链路 Up 与 IP 配置进行中属于不同层次，并不矛盾。
