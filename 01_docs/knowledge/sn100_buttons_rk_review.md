# SN100按钮在RK上的可用性核查

用途：查清按钮点不动或点后没有实际结果的原因，并区分原Windows本来没有动作、移植尚未接入，以及权限、数据或设备条件限制。按钮能发出点击事件、弹出窗口，不等于保存、检测、上传或打印已经完成。

## 当前范围

2026-10-27开始核对。源码盘点覆盖当前正式工程45份页面和弹窗中的367个按钮及选项控件，45份均找到原Windows界面文件。另需核对程序运行时生成的项目按钮、孔位、菜单动作和弹窗。原版只读审查，不运行Windows或WSL本机版本；实际操作在RK完成。

首次只读查看板子时，部署版本为`c89e4a65`，程序正常关闭；当时关闭按钮修复只在当前源码，尚未部署。另一个整合窗口正在更新原数据库版本，按钮实际结果须绑定最终核对的发布编号，不把新源码结论套到旧程序。

## 已有明确原因的项目

| 按钮或操作 | 原Windows依据 | 当前判断 |
| --- | --- | --- |
| 语言设置“应用” | `frmuserset/frmlanguagesetting.cpp`的`on_btnApply_clicked`为空，列表只有简体中文 | 原版本来没有语言切换动作；RK目前提示不支持切换。 |
| 试剂“默认盘面” | `frmreagent/frmreagentmaterial.cpp`的`on_btn_restore_clicked`只定义未调用的局部函数，最终恢复调用被注释 | 原版没有实际恢复，不直接当作移植遗漏。 |
| 分析项目“重分析参数”“算法参数”页签 | 原`frmsystemmaterial.cpp`第86、87行`setHidden(true)` | 原版主动隐藏，当前保持隐藏。这里不代表所有算法业务都不需要移植。 |
| 质控主页“打印” | 原`frm_quality.cpp`主动隐藏 | 不作为已确认的按钮移植遗漏。 |
| 退出确认里的“关闭仪器”选项 | 原`maskdlgshutdown.cpp`主动隐藏该选项；确认默认退出上位机软件 | 软件退出和RK系统关机分开核对。 |
| 主界面红色退出按钮 | 原`frmmain.cpp`明确接到`slotShutDown`，确认后调用退出 | 旧RK版本存在移植缺口；当前源码已有修复，需按新部署版本实际验证。 |
| 报告“保存修改” | 原`Ctrl+Shift+M`显示按钮并进入人工修改；`Ctrl+Shift+N`退出；点击函数实际写结果 | 原版有入口，不能因启动时隐藏认定原版不可用。当前人工结果修改尚未接。 |
| 开始、暂停、样本“校准测试”、曲线审核/重算/选用、报告上传与重算 | 原版有相应点击和业务处理路径 | 当前完整检测、算法或上传流程尚未贯通，属于移植/集成缺口。 |
| 试剂探测、优先使用、更换、耗材等 | 原版有处理路径；当前部分按钮接到`showOffline` | 点击后只提示“未连接”不能当成功能已可用。要继续核真实连接和业务实现。 |
| 仪器操作中的设备动作 | 当前脱机路径统一禁用，新控制代码还受启用参数和连接状态限制 | 逐项核“代码是否实现、是否部署、是否绑定、有没有设备应答”；不能把全部禁用归为原版无动作。 |

原版有处理的结论来自源码，不等于已经在原Windows发行版实际点击通过；原机型、角色、快捷键和设备状态仍可能影响现场表现。资料尚不充分的项目明确保留待确认。

## RK逐项结果如何读

“本轮可见但禁用”只记录当时状态，要结合原因列判断；未选记录、加载中、无权限或未连接时禁用通常是保护条件。“已发送鼠标事件”只说明已触发该入口，完整业务仍需核对数据、文件或仪器应答。弹窗中的取消、关闭和非法输入拒绝不代替正向保存通过。

当前RK共享编译/显示尚未释放，下面逐项结果暂记待RK核对；源码检查不冒充板端通过。
