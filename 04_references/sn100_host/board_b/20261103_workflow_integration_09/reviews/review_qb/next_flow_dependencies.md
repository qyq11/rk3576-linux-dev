# QB接通后：开始流程剩余接线及下一候选依赖

日期：2026-11-03。本文在总控全量04构建期间只读当前正式源码及Windows参考源码，未修改正式、作者候选或公共文档，未运行产品、消息、数据库或板卡。它是下一切片的源码依据，不是功能通过记录。

## 目前实际做到哪里

QB实体键已经进入与软件开始共用的确认、任务准备、当前连接复核及Ts开始命令流程；任务下发后已有占号、报告占位、试剂预扣/退未用、TD进度及Tr原始结果的消费者。不能把这些重列为全部未实现。

剩下三条条件分支尚未接完整：立即下发、下发后删除预设、LIS在线时无本地任务开始。它们不是一个开关补丁；各有后续身份和失败恢复依赖。当前实际INI是否启用这三分支，本次未访问板卡核对，不作假定。

下文“原版”以 `06_programs/sn100_host_reference/Seerain450_PC/` 为根，“正式”以 `06_programs/sn100_host/` 为根。原件只读，不运行参考工程。

## 立即下发：不能仍统一发Ts，也不能伪造一条Tt

**原有效路径。**原 `frmmain/frmmain.cpp:1507–1584` 在主TCP已连接后先判断 `SendTaskImmediate`；true时会询问保存样本草稿，检查所设任务是否含急诊以及急诊舱盖，按主控返回的无水/无杯组合显示不同确认或拒绝，然后改变按钮显示并发内部 `signalPCTaskSend("Emergency", {}, {""})`。Ts调用在1582行被注释，随后return；它不会再经过后面的常规开始检查。信号在404–405行接到样本页 `slotSendRackTasks`。

样本页 `frmsample/frmsamplematerial.cpp:3810–3970` 随之选择真正的Emergency架，按协议分普通/简化编排，调用已有定标和普通任务生成，再保存实际计数并发真实任务命令。不是把开始命令提前发一次。原分支名称有HK6600注释，但实际判断只看开关，不能按注释自行把SN100排除。

**正式缺口。**`original_files/original_runtime_settings.cpp:188` 读到 `debug.sendImmediately`，尚未传给开始流程的消费者。`shell/device_control_shell.cpp:169` 始终排队 `prepareDeviceTasks`，598行后的完成回调始终按常规走 `DeviceControl::start()`；因此true分支没有等价实现。主控无水/无杯原字段已在 `protocol/status_session.cpp:45–49` 的一般字段11/12保留，尚未形成原条件性开始提示。

**最小下一候选。**先在独立候选把“常规开始 / 直接Emergency下发”作为清楚的操作来源接入：把已校验配置值和值身份传给入口；复用现有任务编排、占号和扣量保存能力，但为直接操作建立真实用户意图、连接/账户/资料身份及提交后收尾，不能制造一条“设备发来的Tt”走接收链。正式 `shell/task_reagent_shell.cpp:309–348` 的现有任务桥保存真实到包号、原payload摘要和N/C时点，380行后继续匹配提交凭据；伪Tt会混淆动作来源。

需要核清的依赖：

- 原true分支与常规分支的允许条件确实不同；不能简单把现有全套常规开始门照搬后称等价。连接代次、关闭、会话、正在提交及未知扣量事实的可靠性保护仍须保留，并登记有意差异。
- 真实任务发送成功、入队成功、扣量已提交而发送失败分别处理；不得失败后自动再占号、重复扣量或退量。
- Emergency已存在的任务、CAL/QC及空任务返回按原代码分支核；不重引旧NoReply空架分支，不用电脑或模拟消息验证。
- 与本轮刚合入的逐步骤g6扣退量、任务显示凭据及QB共享 `device_control_shell.cpp`、任务Session和Store，需在冻结后另片编排，不能盖回旧文件。

源码审查、独立候选和ARM64编译可以继续；真实直接任务下发会消费实际任务并可能触发仪器，须有原资料、样本/试剂及当次允许的实物动作范围，条件不足保留待验。不能通过改INI凑出true分支。

## 下发后删除预设：先保留可独立查找的任务身份，再启用删除

**原有效路径。**`TaskSendDelete` 来自原 `main.cpp:67`。普通任务的两套生成函数在样本页2141–2144、2805–2808行先调用 `saveSampleInformation` 再调用 `hole->deleteTask(taskID)`；定标两套在3223–3226、3598–3601行保存定标行信息后调用删除。它与 `TaskFinishedDelete`、`RackFinishedDelete` 两个“完成后清理”开关不同，不能混成一个开关。

原 `saveSampleInformation():2855–2890` 保存task_id、row_id、样本/项目/稀释比、自动编号及QC名称/批号等来源；`saveCalibrationInformation():3659–3672` 保存点位行及最大行号。之后 `slotSampleTesting():4294` 的true分支按task_id更新报告进度；`sampleResultReceive():4749` 按task_id查询报告占位及元信息；`calibratorResultReceive():5159` 也有专用分支。原 `qualityResultReceive():5064` 的true分支是空实现，先如实记录，不能凭函数名补成“已成功处理QC”。

**正式已有与缺口。**`samples/original_detection_session.cpp:252` 已读取该开关，`:403` 明确拒绝true分支。已有reserve在编号、报告占位和剩余量同一数据库连接内提交，内存 `issuedTasks_` 保留当前运行的任务身份；这部分应复用。可是TD在665行、Tr完整收尾在805行仍必须调用 `OriginalSampleRepository::updateDeviceTask`；该函数 `original_sample_repository.cpp:379–401` 要找到现有架/孔/项目/重复项。直接删除预设或只去掉403行保护，会让晚到进度、结果、TR和重连恢复失去有效归属。

**最小下一候选。**先独立补原保存元信息及“任务已发后不依赖当前可编辑预设”的后续查找/进度/结果收尾，保持实际issued身份、任务计数和已提交试剂量；待SAM、CAL、QC原实现边界和TR退未用均对齐，才另片开启删除。删除应只影响原指定预设，不能顺便清 `issuedTasks_`、退款依据、结果占位或用户新建任务。若跨重启无法确认旧已发身份，继续明示待核，不能从当前最大编号猜归属。

原实现还有两项必须继续窄核，不能擅自“修好”成新规则：

- 普通/定标生成函数在调用deleteTask后，附近仍可能把局部holeTask重新设回页面；应核实际对象、局部副本和调用顺序，不能只凭开关名称推定所有画面删除生效。
- 原元信息写入日目录，而 `frm_report/report_string_pasher.cpp:227–267` 的结果保存使用月目录或calibration目录；CAL结果读取也有不同目录。需按真实最终路径链核对，不在本片统一改目录。保留用户资料及已有结果，不靠迁移/清理掩盖差异。

元信息及身份消费者的源码候选可继续准备；真实下发后删除、晚到TD/Tr/TR、重复返回、重连/重启恢复必须在原资料和真实仪器条件分别验证。未具备结果计算算法不阻止保存原始曲线和身份的源码推进，但不能声称最终计算结果通过。

## LIS在线且无本地任务：下载链未接，不能只删“没有任务”的拒绝

**原有效路径。**原 `frmmain/frmmain.cpp:1743–1762` 只有在“自动取任务关闭”或“LIS未连”时才要求本地存在普通/定标任务；自动取任务已开且已连时可以继续常规开始。然后主控真实Tt到达，`communication/commandreceiver.cpp:300–360` 解析架号、孔位扫码和已收任务号；条件仍满足时发 `signalPCGetLisTasks`，否则走本地预设。

原样本页 `slotPCGetLisTasks():3973–4158` 处理实际架/孔、条码和原报告状态，建立逐孔查询状态，用 `LisCommSetting::QRYMessage` 生成真实查询，记录超时/发送，再等待回包；无查询可发的分支才回到本地任务。`slotRevLisLisTasks():4160–4280` 使用收到的任务/患者资料再调用真实任务下发。原4080行附近的 `send=true; //这块临时问题` 会覆盖前面的重复样本判定，迁移时必须如实核其有效行为，不能只照前面的“不可重复”说明重设计。

**正式缺口。**本轮LIS连接已具有原配置、编码、配置版本、真实socket代次及完整正文身份；不能重列为“LIS完全未做”。但：

- `shell/lis_shell.cpp:53` 当前只画连接图标/说明，未把已提交autoGet和当前连接身份交给开始业务门。
- `shell/device_control_shell.cpp:327–331` 无条件要求本地任务；后台 `samples/original_detection_session.cpp:434` 也要求有任务或未完成任务。
- `samples/original_sample_store.cpp:365` 收到真实Tt始终走本地 `answerRackRequest`，没有LIS/本地来源分流。
- `shell/main.cpp:1463–1474` 的完整LIS正文目前只记 `LIS_MESSAGE_NOT_APPLIED`，明确 `ack_sent=false task_saved=false`；无真实患者/任务写入消费者。
- `lis_transport/LisConnectionController` 已有带配置版本/连接代次的发送和接收接口；`lis_raw_inbox/LisDsrRaw` 仅是明确UTF8原始DSR解码/独立收件箱，不生成任务、不等于下载业务，更不能用raw-inbox本地编号冒充任务号。

**最小下一候选依赖顺序。**

1. 原查询/回应字段和身份值对象：先确认实际配置的角色、编码和医院端协议；保留MSH控制号、连接配置版本/代次/对端、真实Tt架孔与样本条码之间的对应关系。现有传输结果只说明字节处理，不是对端业务确认。
2. 真实Tt分流及逐孔查询在途：只有已提交autoGet和同一有效LIS连接共同成立时进入查询；有界等待、断线/改配置取消、重复/晚到回应、原条码占用和架完成重建必须明确。无LIS时原本地链继续成立。
3. DSR等实际回应的字段校验→所属工作线程保存患者/任务→完成后再按原规则确认/下发；错误不得先回成功ACK，无法归属不得保存到其他架孔。不得在GUI执行SQL。
4. 上面链完整并能拒绝未就绪分支后，再把开始的“无本地任务”条件改成“本地任务或已就绪的真实LIS下载能力”；后台prepare也需接同一许可，不能只改UI门。LIS在开始确认期间断开或改配置时重新核对，不由绿色图标续期。

源码格式和消息交接可以继续独立候选、交叉编译；真实端点的查询、患者/任务保存、确认和随后主控下发都需要原医院端/资料及当次允许范围。没有真实端点时记录待联机验证，不建模拟服务器、匿名患者任务或伪造回包来关闭它。

## 建议下一次具体派工

继续沿原功能聊天分工，不另开重复窗口。先让同步/任务作者准备“立即下发操作来源与独立Emergency入口”的最小候选，并把上述真实Tt凭据区别写清；校准/质控作者核删除分支的元信息与后续身份；LIS作者先交查询/回应字段和真实Tt交接候选，暂不放宽无任务开始。三者先各自独立审查，公共开始入口、任务Session/Store和main由总控串行合并。
