# RK项目配置专项响应测量

正式源码和正式验收驱动已经固定。本文件与`original_project_page_profile.cpp`只放在temp，供根窗口单独交叉编译并在RK运行；不改正式程序，也不在Windows或WSL运行功能测试。

旧`page_02/page_result.json`的114项功能检查全部通过。其10ms心跳跨越整个测试过程，混入了测试代码在界面线程执行的`QWidget::grab()`、PNG压缩和写文件、逐表SQL完整内容指纹、DB文件SHA、原参数/单位/文件选择弹窗。这些数据只能说明整组测试期间观察到的最大间隔，不能直接归因为产品DB同步写入。原保存反馈计时在`ensureWidgetVisible()`之前开始，混入了滚动布局开销。

只读检查`ProjectPage::save()`：业务入口先读取控件并校验、生成值快照，再排队交给`ProjectsStore`工作线程；没有直接SQL或文件读写。界面仍同步进行`setBusy()`、`updateActions()`和读回后的`showProject()`控件重建，所以异步DB并不等于所有操作都满足响应要求，须独立测量。

专项驱动使用实际`ProjectPage`和实际原库工作线程，输入为专用原工作副本中的7项目、7单位，普通保存反复修改PT的LIS代码，再恢复原值。SQL仅在测量区间外建立/释放一次真实写锁；无SQL内容审计、文件指纹、截图、PNG、额外参数菜单或导出。只有写锁失败时产品本来会弹出的错误窗口由驱动点击关闭，不隐藏该错误窗口的影响。输入、滚动和等待界面稳定在测量区间外完成；鼠标按下前开始计时。

参数：`--data-dir <RK专用原工作副本> --output-dir <新证据目录> --iterations 12`。依赖与正式原库页面驱动相同，替换入口源文件即可；输出`page_profile.json`。根窗口独占部署和RK执行。

每次记录：

- `sendMouseEventReturnMs`：发送实际鼠标按下/松开直到同步调用返回的时间，包含保存输入校验、设置忙碌和控件同步更新，不含预先滚动。
- `busySignalMs`：页面从鼠标操作开始到发出忙碌状态信号的时间。它说明软件状态反馈，不能单独证明屏幕已经画出禁用效果。
- `saveReceiptMs`：实际保存成功或失败的页面回执时间。
- `busyFalseMs`：解除忙碌状态信号时间，通常在保存成功、重新读取原DB、重新生成编辑控件后；信号后的少量控件启用更新尚未包含在该时间点里。
- `loadReceiptMs`：页面完成读回处理的回执时间，包含busyFalse之后的动作更新；写失败没有读回时为-1。
- `heartbeatGaps`：10ms精确定时器在本次业务操作区间内的实际相邻处理间隔，包含末尾15ms观察。它是界面事件循环阻塞代理指标，包含正常绘制、布局与内嵌错误窗口开销，不能代替实屏输入和绘制验收。

单列初始加载、正常保存、写锁失败、解除后不重新输入直接重试、恢复原值和明确重新读取；不会混用不同操作的p95。样本数写在输出里。没有预设性能通过门槛；测量完成仍须解释剩余阻塞来源，不得因为114项功能通过或DB放到工作线程，就声称不卡顿、长稳或同板实时控制通过。
