## 1. 重启后的板端结果

用户在本地登录后执行：

```text
ip -4 -br addr show end0
end0    UP    192.168.100.123/24
```

`nmcli device status` 显示：

```text
end0    ethernet    connected    rk3576-direct
```

**结论：**结合用户的重启说明，固定 IPv4 地址在本次重启后仍为 `192.168.100.123/24`，NetworkManager 已自动使用 `rk3576-direct`。固定 IP 配置及本次重启持久性验证通过。

本次证据没有显示创建命令的完整执行过程或配置文件路径；不据此补填未检查的 UUID、保存文件名等信息。

## 3. 本次实际检查 SSH 服务端口

从当前 Windows 主机向目标 IPv4 的 22/TCP 发起一次连接并读取服务标识，得到：

```text
192.168.100.123:22 TCP端口可达。
SSH-2.0-OpenSSH_9.6p1 Ubuntu-3ubuntu13.19
```

同时读取邻居表：目标 `192.168.100.123` 在“以太网”接口上为 Reachable，MAC 为 `3E-C3-C5-4E-C4-22`，与此前板端 `end0` 的 MAC 一致。

**已确认：**目标板卡身份与接线记录一致，当前 22/TCP 可达并提供 OpenSSH 服务。无需仅为开始登录而重新安装 SSH。

**尚未验证：**`lckfb` 用户能否完成 SSH 认证、远程命令能否执行；服务具体配置、认证策略和启动单元未读取。端口检查不等于登录成功。本次未输入密码、未建立认证后的远程会话，也未修改板端配置。

## 4. 下一步：Windows 发起 SSH 登录

保持网线连接及开发板供电，在 Windows PowerShell 中执行：

```powershell
ssh lckfb@192.168.100.123
```

首次连接确认目标主机密钥后继续，输入板卡本地 `lckfb` 账号的登录密码。密码输入时通常不会显示字符。

登录成功后，在同一个窗口中执行：

```bash
whoami
uname -r
ip -4 -br addr show end0
```

预期分别看到 `lckfb`、`6.1.99` 及 `192.168.100.123/24`。保留登录及命令输出后，可完成 T02 的远程登录验收；结合本次重启后的端口检查，记录本次启动后的 SSH 可用情况。使用 `exit` 返回 Windows PowerShell。
