# 07实际AD显示证据的独立只读审查

`review_actual_ad_07.py`用于核对本次真实运行中，主控发来的AD文字是否确实进入仪器页的1至24通道、每行4格。它只用Python标准库读取已经取回电脑的证据，不运行上位机，不联网，不发送命令，不执行采集、归档、冻结、绑定、构建或原有汇总工具，也不改原日志、原JSON、9份冻结模板、06文件或正式源码。

当前只完成源码阅读和AST语法检查，尚未处理07实际case，也没有用06实际结果代替07结果。等唯一采集方确认本次数据已经取回并给出绝对目录后，再由其执行。

## 调用方式

```text
python review_actual_ad_07.py ABSOLUTE_CASE_DIRECTORY ABSOLUTE_BINDING_DIRECTORY
                            [--output ABSOLUTE_NEW_REPORT_JSON]
```

两个输入目录都必须是明确的绝对路径。脚本不猜case目录，不读取板端远程路径，也不查找“最近一次”结果。默认只向标准输出写JSON；给出`--output`时，只新建一个尚不存在的绝对路径报告，拒绝覆盖已有文件，父目录须已经存在。退出0表示本脚本列出的AD证据一致；退出1表示证据缺失、不一致或AD比较失败；指定报告无法安全新建时退出2。

case目录使用本批冻结采集方式已经确定的文件名：`app.log`、`identity.txt`、`results/result.json`和`shutdown_contract.json`。只接受`MODE=auto`、板B以及与本批绑定相符的结果；不替人工输入或管理员口令登录作证明。

绑定目录读取本批`prepared_inputs.json`、`link_provenance.json`、`execution_07_result.json`、`execution_07_inputs_before.json`、`execution_07_inputs_after.json`、`source_snapshot_07.json`、关闭合同、prepared列出的9份模板和4份合同文件，以及`status_login_review_07`和`review_release_id`。

## 本批身份从哪里来

脚本没有写死06或07的发布校验值、应用校验值、检查程序校验值、源码校验值、源码数量或对象数量：

- 发布身份、正式应用、main源码、源码包和源码数量从07的prepared正式来源读取，和link、实际构建结果、构建前后记录、case身份、结果JSON及日志发布标记交叉核对。
- 对象数量从link读取，核对象列表连续、唯一正式main保留，和实际构建结果及前后对象校验清单交叉核对；不把冻结阶段`object_count=null`当成最终数量。
- 检查程序校验值从实际`execution_07_result.json`读取，并计算当前`status_login_review_07`实际文件校验值核对。prepared中的`prepared_checker_sha256`是检查源码校验值，不能误当已构建程序校验值。
- 检查源码和AD观察头校验值从prepared模板清单读取，与实际文件、link绑定及execution构建来源交叉核对。检查链接记录自身身份、prepared文件身份，要求构建前后输入文件完全相同；要求冻结、构建、依赖检查的真实退出码均为整数0。

本脚本核对绑定记录和当前模板、检查程序等直接输入；不会再执行正式构建或全源码、全对象验收流程。正式663份冻结源码和277对象的逐文件独立核对见同目录`final_07_inputs_review.md`，此脚本不把元数据交叉一致扩称为重新完成了该轮检查。

## AD文字如何独立核对

脚本先要求本次检查完整结束、失败数为0、24项逐项结果均通过，再定位冻结检查源码中三条真实PASS日志：清除旧连接AD值、恢复实际主控连接、完成新连接AD比较。它只解析清除之后、AD比较之前的原始RX窗口，不从窗口外补旧值。未知格式、缺帧、缺片、重复或乱序分片、观察计数不一致都会失败。

RX解析根据原Windows帧格式独立实现：检查06/07帧头、大端长度、四字节分片头、异或及08/09帧尾，支持半帧、多帧和跨帧分片；没有导入正式协议解析器或C++观察器来计算预期值。只把该窗口实际收到的Qq用于AD预期，其他命令内容不写入独立报告或标准输出。

对最新Qq，只消费声明数量前N对完整键和值；同一完整键第一次值生效。额外尾Base等字段单独保存，不塞进通道表。按原空格拆分保留空项，只取前4项；要求实际原RX本次提供完整1至24通道的96格。键必须完整相等，`01`不会合并成`1`，不固定界面行号，不要求Base或HIL额外显示行。

脚本逐格比较结果JSON保存的`table_rows_at_comparison`实际字符串与实际布尔`reported=true`，同时交叉核对本次覆盖范围、观察器原Qq、十六进制、末32条Qq历史、帧和消息计数、重复键、忽略尾字段，不能只凭`passed=true`放行。报告保存本次独立解出的最新Qq、行号边界、96格实际表格、逐格差异及输入文件校验值；不会输出整份app.log、identity原文、其他业务帧或认证资料。

## 能证明和不能证明的范围

连接代次只要求本次`new_generation > old_generation`，观察代次和比较代次等于该新代次；不写死3、5或其他历史数值。RX包字节本身没有socket数值代次字段，脚本不能从包字节独立推出代次数字，因而同时使用已冻结检查器JSON、清除/恢复/比较日志顺序和该窗口完整RX计数限定来源。若不明重连造成窗口与观察器不一致，保守失败，不回退到旧连接快照。

清除前没有另存逐格表格快照，因此脚本只能核对冻结检查器的清除结果、至少96格的检查范围及真实日志边界，不能声称自己重新读取了当时每格界面。值始终按原字符串比较；`65535`等字符串即使原样显示且已上报标记为真，也不能据此认定物理测量有效。

本批关闭合同须是07格式，绑定本批main，含18条真实标记及`REAGENT_LEVEL_SHUTDOWN_READY active false worker_busy false`。脚本只核合同身份和验收范围，不替既有`summarize_run.py`逐条验收运行日志。完整TX仅Qj范围、18条退出合同、实际应用和封装退出码、配置是否改变及主控是否保持，仍由既有汇总工具负责。

独立报告始终把`n_function_verified`和`in_flight_n_close_verified`保留为false；本次原24项与AD96格不能证明N试剂液位的接纳、写入、重载、同仪器上下文显示或提交中关闭。真实管理员口令、实体键鼠/屏幕、机械动作及检测功能也不在本脚本验收范围内。
