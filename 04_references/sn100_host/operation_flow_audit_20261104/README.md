# Windows 原操作流程与当前移植的全面静态复核

仍有类似移植差异，而且跨越样本、组合、试剂批组、质控、校准、报告和全局导航。共同问题是新增/选中/点击复选框原来已经生效，移植时被改为最后统一保存；或者原来仅切页/局部刷新，被改成全局放弃确认或整页重读。页面、类和按钮虽然存在，使用者照原步骤操作仍可能得到不同结果。

## 原分支和已知特殊动作不能混淆

- 文件夹名Seerain450_PC、工程名SN100、页面主题SN500并不能代替实际机型配置。样本孔数和容器按原INI，容量选择按SN450/其他分支；isNewProtocal、LinuxNew是原程序实际读取的协议/设备字段，不能由移植所运行的操作系统擅自替换。Simple/非Simple检测报告分组、人工快捷报告新增、LIS应用计划是不同用途，详细证据见结果明细。

- 某些原SQL失败会留下部分更新，原项目选择窗口X可能产生特殊副作用，某些输入错误后原弹窗仍关闭。本次如实登记；本轮既不自行修原缺陷，也不把新事务/新保护默认为用户已批准的行为改变。绑定参数、线程或平台API可以不同，可见行为是否一致须单独证明。

## 为什么差异这么多

普通新增、编辑、保存、取消本应直接沿用原规则，不需要重设计。当前差异有可查的历史：早期先做独立本地页面时采用了新的草稿/持久化模型，医院源码还明写“有意”的确认和原子保存；后来接原配置、原数据库时，部分新模型继续保留。旧检查再按新模型期待的结果执行，证明了新实现内部能运作，却没独立逐步证明原Windows相同。前几轮核查重在功能和正式接线，操作顺序的对照不够，漏掉了这类问题。
