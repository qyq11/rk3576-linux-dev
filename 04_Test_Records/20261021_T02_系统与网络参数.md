## 2. `cat /etc/os-release`：系统标识

`cat` 显示文件内容，`/etc/os-release` 是当前镜像提供的系统标识文件。以下版本按照片中的实际字符串记录，不能单凭这些字段确定 SDK 源码版本、官方镜像文件名或软件包是否全部更新。

| 字段 | 照片中的值 | 含义与用途 |
| --- | --- | --- |
| `PRETTY_NAME` | `Ubuntu 24.04.5 LTS` | 面向用户显示的完整系统名称；LTS 表示长期支持版本 |
| `NAME` | `Ubuntu` | 发行版名称 |
| `VERSION_ID` | `24.04` | 供脚本和软件识别的发行版本号 |
| `VERSION` | `24.04.5 LTS (Noble Numbat)` | 镜像声明的详细版本及发行代号；`.5` 为该文件声明的点版本 |
| `VERSION_CODENAME` | `noble` | 发行代号，常用于区分软件源对应的发行系列 |
| `ID` | `ubuntu` | 供程序识别的发行版 ID |
| `UBUNTU_CODENAME` | `noble` | Ubuntu 的发行代号 |
| `ID_LIKE` | `ubuntu` | 当前镜像声明的相关发行版标识，按照片原值保留 |
| `LOGO` | `ubuntu-logo` | 系统图标标识，与网络配置无关 |
| `HOME_URL` / `SUPPORT_URL` / `BUG_REPORT_URL` / `PRIVACY_POLICY_URL` | 照片可见 Ubuntu 官网、帮助、缺陷报告与隐私政策链接 | 系统信息中的参考入口，不是开发板 IP、网关或 DNS |
| `BUILD_INFO` | 构建字段包含 `Sat Sep 12 11:17:33 CST 2026` | 当前镜像附加的构建信息，时间字符串对应 2026-09-12；构建主机名未作逐字转录 |
| `RK_BUILD_INFO` | 构建字段包含 `Sat Sep 12 11:17:47 CST 2026` | Rockchip 相关构建元信息；不据此推定当前运行于虚拟机 |

`BUILD_INFO` 与 `RK_BUILD_INFO` 是本镜像可见的附加字段；其中出现 `root@…-virtual-machine` 描述构建环境，不能据此判断运行中的泰山派是虚拟机。构建字段中的时间也不是照片记录日期、当前板端时间或上电时间。

## 3. `uname -a`：运行中的内核与架构

照片可读的输出转录如下：

```text
Linux localhost 6.1.99 #1 SMP Sat Sep 12 10:42:59 CST 2026 aarch64 aarch64 aarch64 GNU/Linux
```

| 内容 | 含义 | 对后续开发的作用 |
| --- | --- | --- |
| `Linux` | 内核名称 | 确认当前运行 Linux 内核 |
| `localhost` | 当前主机名 | 是设备名称，不是可直接用于 Windows 远程登录的板卡 IP |
| `6.1.99` | 当前内核发行版本 | 后续驱动、内核模块和设备树工作需要匹配实际内核及厂商源码 |
| `#1` | 此内核报告的构建标记 | 不表示 CPU 核数或用户编号 |
| `SMP` | 内核支持对称多处理，即多 CPU / 多核协作 | 不直接给出本机实际核心数量 |
| `Sat Sep 12 10:42:59 CST 2026` | 内核构建时间字符串 | 用于区分构建，不是当前时间或运行时长 |
| 三个 `aarch64` | 分别报告机器硬件名、处理器类型和硬件平台；此构建三项都返回 aarch64 | 表示 64 位 ARM 架构，选择预编译软件时需匹配 ARM64 / aarch64 |
| `GNU/Linux` | 操作系统标识 | 与 Ubuntu 发行版名称属于不同层次的信息 |

Ubuntu 的 `24.04` 是发行版版本，Linux 的 `6.1.99` 是内核版本；两者含义不同，不要求数字一致。`uname -a` 不能确认当前系统的源码提交、完整内核配置或 SDK 存放位置。

## 4. `ip -br addr`：网络接口状态及地址

`ip` 查询网络信息，`-br` 表示简洁输出，`addr` 表示地址。照片中可见：

```text
lo       UNKNOWN    127.0.0.1/8 ::1/128
dummy0   DOWN
end0     DOWN
wlan0    DORMANT
```

| 接口 | 照片状态 / 地址 | 解释 |
| --- | --- | --- |
| `lo` | `UNKNOWN`；`127.0.0.1/8`、`::1/128` | 回环接口，用于板卡内部程序访问本机；其 UNKNOWN 状态本身不表示故障 |
| `dummy0` | `DOWN`，地址栏为空 | 按名称通常为虚拟占位接口，不是本次优先配置的物理网口；如需严格确认类型，可再查 `ip -d link show dummy0` |
| `end0` | `DOWN`，地址栏为空 | 本机有线网口的待排查接口；当时未处于可正常传输数据的运行状态，也没有显示 IP 地址。不能仅凭此分辨网线未接、对端未就绪、接口未启用等原因 |
| `wlan0` | `DORMANT`，地址栏为空 | 无线接口处于等待协议或外部事件的运行状态，尚未显示 IP；仅凭此不能确定 Wi-Fi 连接、认证或驱动的具体状态 |

注意接口名是 **`end0`，最后一位为数字 0**；后续配置以实机名称为准，不直接套用其他教程中的 `eth0`。

`127.0.0.1` 是 IPv4 回环地址，`::1` 是 IPv6 回环地址；Windows 上访问这些地址会指向 Windows 自己。`/8`、`/128` 是网络前缀长度，不是端口号，其中 IPv4 的 `/8` 对应掩码 `255.0.0.0`。目前照片中只有回环地址，没有显示供 Windows 通过局域网访问开发板的地址。

## 5. `ip route`：路由信息

照片显示用户多次执行 `ip route`，每次均直接回到提示符，没有路由行，也没有可见报错。

- `ip route` 默认显示 IPv4 主路由表；本次输出为空，表示当时该表没有可见路由条目。
- 没有看到到局域网的直连路由或 `default via ...` 默认路由；默认路由通常用于把发往其他网络的数据交给网关。
- 空输出不表示命令卡住，也不需要单纯重复输入来等待结果。
- 这不等于所有路由表或 IPv6 路由都为空；回环相关路由可由系统维护在 local 表中。
