# 未来实际06联机结果的独立AD复核

`review_actual_ad_06.py`只用Python标准库读取本次取回的case目录和本次最终06绑定目录。它不运行上位机，不发送请求，不联网，不执行归档、冻结、构建或既有汇总脚本，也不改原始日志或JSON。当前只完成AST语法检查和人工源码阅读，尚未处理实际数据或旧05结果；须等总协调提供本次实际case后再执行。

调用接口为：

```text
python review_actual_ad_06.py ABSOLUTE_CASE_DIRECTORY ABSOLUTE_BINDING_DIRECTORY
                            [--output ABSOLUTE_NEW_REPORT_JSON]
```

两个输入必须是明确的绝对路径。case内相对文件名来自当前冻结runner的真实保存方式：`app.log`、`identity.txt`、`results/result.json`、`shutdown_contract.json`。绑定目录使用已生成的prepared、link、contract及已冻结的专项cpp/AD观察头。脚本不猜测将来的实际case路径。默认只向标准输出写JSON；只有明确给`--output`时才新建报告，已有文件一律拒绝覆盖。退出0仅表示本脚本所列AD证据一致，不能代替整套联机验收。

复核内容包括：

- 最终06发布、应用、专项程序、专项cpp和观察头身份，以及prepared/link/合同一致；拒绝把旧05输入当06。
- `completed=true`、`failed=0`与逐项结果一致；新代次严格大于旧代次，观察代次相同，无半帧、缺片或错误遗留。
- 依据已冻结cpp中的真实PASS检查文字，定位“清除旧连接AD值”之后、“本次新连接AD比较”之前的RX窗口；不从窗口外补数据。
- 从`app.log`实际RX十六进制独立检查06/07帧头、大端长度、分片头、异或和08/09帧尾，处理半帧、多帧和分片。没有导入正式程序或C++观察器的解析结果来计算预期值。
- 按声明数量前N对组成通道表，重复完整键首次值生效；额外尾Base等字段另存。空格拆分保留空项，核最新本代原Qq确实提供1至24通道的96项。
- 对`table_rows_at_comparison`里的完整字符串键逐行核四项实际文字及四个布尔reported标记，不固定行号、不把`01`并为`1`，不要求Base/HIL额外行。
- 原Qq文字、十六进制、末32条历史、帧/消息/分片计数、声明数量、重复键、忽略尾字段，与独立RX解码结果相符；不能只凭`passed=true`或沿旧05数值通过。

范围限制会写进报告：RX包字节本身不含socket数值代次，数值代次来自已冻结检查器JSON，另用实际清除/重连日志边界交叉限定；不能声称独立从包内容推出代次。清除前逐格状态没有另存完整表，脚本只能核冻结检查器的清除记录与日志边界。若该窗口内发生多次不明重连、原始RX缺失或记录不完整，脚本保守失败，不拿旧快照填空。

`65535`等值按原字符串比较，不判断其物理有效性。完整启动至退出的TX仅Qj范围、17项退出合同、实际应用wait码、timeout封装码、配置是否变化及主控是否保持，仍由原有`summarize_run.py`负责。本报告不冒充这些项目已通过，也不证明真实管理员口令、实体键鼠/屏幕或机械检测功能。
