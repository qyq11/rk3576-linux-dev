# 业务可读性与运行验收

这里是 SN100 的项目约定。已有风格保留在局部 AGENTS，待办和阈值保留在当前模块卡，实际数据保留在统一移植记录；本文件不维护另一套进度。

**2026-10-27起的执行方式：**电脑只用于源码检查、ARM64交叉编译及上传，不再运行Windows/WSL本机版本做功能、界面或资源测试，也不安排Windows测试构建。每项改动直接在RK验证；以下“原版对照”使用只读源码、已有截图与用户提供的信息，“资源测量”使用RK实测。历史电脑证据不改写；RK暂不可达时登记待RK验证。

## 原版界面保持与最小适配

用户于 2026-10-23 明确要求：移植界面尽量保持原版颜色和布局，仅做 Linux / RK3576 屏幕所必需的调整。本要求从当前模块起适用；已完成的离线功能用例不能证明其视觉一致。

- **先确定原版视觉依据。** 对应原 Windows 发行版/机型/主题，读取原 `.ui`、局部和共享 QSS、C++ 动态样式、图标/QRC及主题加载链；结合已有原版截图确认普通、选中、禁用、错误/告警、弹窗等状态。不能只复制控件名称，或只看 `.ui` 后用另一套默认主题补齐。参考包继续只读，不启动原工程或沿用旧连接/生产配置；需要实际主题值时使用用户已提供或明确可用的非敏感依据，不顺带读取凭据或生产库。
- **默认保留视觉与操作习惯。** 保持原配色、字体风格/大小层级、边框/圆角、图标和文案、导航/按钮顺序、业务分组、控件相对位置/比例及重要状态含义。代码分层、数据 worker、事务或算法改造不意味着允许重做页面；单模块脱机入口也保留原业务区域，不换成卡片、仪表盘或自选蓝色主题。
- **必要适配须有具体原因。** 可处理 Linux 缺失字体的近似替代、资源路径大小写、DPI/字体度量差异，以及目标屏幕导致的裁切、遮挡和不可操作。先保留原版设计比例与层级，针对实际问题调整；确需布局管理器、尺寸/间距调整或局部滚动时，保留原分组和操作顺序，复核前后视觉与交互。不能仅因目标为 Linux 就全面重排页面，也不通过非等比拉伸破坏图形或点击命中。
- **实验说明与业务界面分开。** 脱机/无设备提示放启动参数、日志或不挤压业务区域的独立宿主说明；不得为展示“移植成功”向原页面增加大标题、说明卡、横幅和新工具栏。确有必要的状态提示沿用原有区域和样式；实验辅助控件不自动进入正式界面。
- **差异逐项可追溯。** 在当前模块卡/同一移植记录说明“原版依据 → 原表现 → 移植后表现 → 平台/屏幕必需原因 → 核对结果”，覆盖颜色/主题、布局/间距、字体/图标和交互状态；不能把所有差异笼统归为“Linux 适配”。缺原版截图或主题事实时保留源码样式、记录未知项，先做有依据的部分，不凭偏好重新设计或宣称视觉通过。用户明确要求的重新设计另行记录范围；当前要求不授权重新设计。
- **视觉验收独立取证。** 在RK按相同页面、状态、匿名数据及明确分辨率/DPI取证，与原版只读源码、已有截图和用户提供的画面核对，不新跑Windows/WSL版本。保留原图，标注允许的差异、依据和待验项；缺原版画面时明确待核。明显配色/布局改变且无必要性依据，记为待纠正，不能以功能相同或编译通过放行。

## 1. 人读得懂、能修改的代码

- **按业务叫名字。** 用医院名称、字典类型、样本号、任务状态等已确认术语，避免 `doWork()`、`handleData()`、`flag1`、单字母业务变量和只有作者懂的缩写。沿用原接口所需名称时，用薄适配或注释解释，不全库改名。
- **入口到结果能追踪。** 例如“保存医院名称”应能看出：读取输入 → 校验 → 提交保存 → 收到结果 → 更新界面或显示失败。没有复杂规则时直接的页面加存储调用即可；确有业务判断时提取 `validateHospitalName()` 等有意义的步骤，不为每一步建立抽象接口。
- **一个函数表达一件完整的事。** 嵌套条件、重复判断或多种职责遮住主流程时拆分；不设机械行数上限，不把几行清楚逻辑拆散到十几个跳转。成功路径可顺读，失败尽早明确返回，异步结果带请求标识，不能让过期回复更新新选择的记录。
- **业务与实现细节有边界。** 页面处理输入/展示；业务规则决定能否操作和状态变化；协议负责编解码；传输负责连接/收发；存储负责事务/字段映射；平台层集中 Windows/Linux 差异。只创建本模块真正用到的部分，不让 QWidget 指针穿入算法或协议对象。
- **注释解释原因和约束。** 关键业务判断、状态转换和计算用简短中文说明目的与依据，写清规则来源、单位、范围、协议字段、兼容原因、线程归属、所有权和副作用。不要逐句翻译 C++ 语法。历史命名无法改时注明含义；未知规则记录待确认，不用 TODO 掩盖必需功能或空实现返回成功。
- **数据和错误可以理解。** 值对象字段表达业务含义，枚举表达状态，常量写明单位；不以位置魔数和若干不明 bool 组合承载业务。错误应能区分输入、连接、协议、存储或算法失败，告知可采取的下一步；保留排查所需上下文，避免只有 `false` 或“失败”。
- **生命周期清楚。** Qt 父子所有权、局部 RAII、智能指针按对象实际生命周期选用；说明谁创建、在哪个线程用、谁关闭。避免两种所有权重复释放，也不为“现代化”把所有 QObject 改为智能指针。
- **重构行为可对照。** 先固定典型输入/预期输出及异常，再改结构；业务行为变化单独说明。测试重点是字段/规则/状态/报文及恢复，不是复述函数实现。交付时给维护者指出入口、关键规则、数据落点及一条最小复现路径。

人审自检：接手者能否回答“入口在哪里、规则在哪里改、结果存到哪里、哪些操作会发设备命令、失败后会怎样”？回答依赖跨越大量无意义包装时，先简化设计。

## 2. Qt5 下的响应、线程与数据可靠性

- QWidget 仅在 GUI 主线程访问。GUI 回调不做 `sleep`、阻塞式 `waitFor*`、长重试、重计算或大批同步磁盘/SQL 操作。异步 socket 可以在 GUI 线程，但回调应短小且不积压；不要求每个 I/O 都起新线程。
- QObject 的事件由所属线程处理；socket、timer 在正确线程创建/使用，计时器在所属线程启停。QThread 对象通常属于创建它的线程，不能认为其普通成员槽自动运行在 `run()` 线程。适用时用 worker 对象与 `moveToThread()`，跨线程结果通过排队信号槽和值快照传递，不共享可变 UI 状态。
- Qt5 SQL 连接应在使用它的工作线程创建和使用，不能把 GUI 线程创建的连接交给 worker。参数绑定、事务、提交失败回报和关闭顺序明确；界面不能在提交成功前显示已保存，迁移数据库前核查受影响数据和恢复范围。
- 定义停止顺序：停止新任务 → 完成或取消在途请求 → 关闭通信/数据库 → 退出线程并等待 → 释放对象。覆盖关闭窗口、重复进入页面、错误重试和重开；不依靠 `terminate()` 或嵌套事件循环硬解卡顿。
- 采集、业务处理和界面显示频率可以不同；曲线缓存、模型、在途请求、日志缓冲都有容量与增长策略。纯显示可合并最新值，必要原始数据、任务和告警不能静默丢弃；过载要背压或明确失败，设备控制动作不能因超时盲目重发。
- 协议用例按模块覆盖拆包/粘包、长度/校验/枚举、断线、超时、重复与乱序；保留具体 TX/RX，并区分回放、模拟和仪器返回。日志有分类、轮转和空间不足处理，敏感数据脱敏。

## 3. 把“稳定、不卡顿”写成可验收要求

先把以下字段落到当前模块卡，已有明确值直接沿用；未知值标记“待确定”，允许做基线测量，但不能声称满足未知门槛。

| 项目 | 需写清的条件与观察值 |
| --- | --- |
| 输入/负载 | 数据行数、输入速率、并发任务、持续时间、查询/导出/曲线等操作组合；匿名固定数据可复现 |
| 运行条件 | OS/架构、Qt/编译器/依赖、Release、QPA/显示栈、分辨率/DPI/字体/输入设备、CPU/调频/散热、其他进程 |
| 交互响应 | 从用户操作到可见反馈/完成的起止点，样本数，p95/p99/最大值和失败数；反馈延迟与任务完成时长分开 |
| 事件循环 | 单调时钟测定时器计划与实际处理的延迟分布/最大间隔；注明采样周期；它是阻塞代理指标，不能替代实际绘制/输入验收 |
| 资源 | 进程/整机 CPU 及口径、RSS/PSS/峰值、线程/FD、队列积压、数据库/日志/磁盘增长；PSS 取不到时注明，不能记为 0 |
| 稳定性 | 无崩溃、死锁、非预期退出、持续无界增长、数据损坏/丢任务；记录持续时长、操作次数、重启/异常恢复及残留缺陷 |
| 同板控制 | UI/算法运行前后在相同控制负载下的时延/最大值、deadline miss 和资源变化，按控制需求门槛判断 |

若用户尚无时间指标，可提出**项目初始候选**：普通按钮/页面操作可见反馈 p95≤100 ms、最长无响应≤500 ms；导出/算法等长任务异步给进度、失败和适用的取消，完成时长另约定。这些数值不是行业标准，也未在 RK 验证；业务负载与阈值明确后才形成放行门槛，不能拿候选值宣布通过。

先做短时冒烟，再按计划考虑 2 小时回放、8 小时业务负载和 24–72 小时长稳；这些是分级测试候选，具体时长与负载写入模块/整体验收，不因运行时间够长而忽略错误，也不以几次点击代替长稳。

## 4. RK3576 的可行性判断

已有 Qt 最小示例能在板上运行，只证明基础链路；当前完整 SN100 的依赖、算法、画面、存储和同板负载需分别验证。WSL x86_64 的响应/资源数据只用于该环境，不折算成 RK 达标。

上板前核对 ELF AArch64、Qt/ABI、依赖库、QPA 插件、字体/输入与实际显示后端；已有 sysroot/备份和 Qt 环境记录优先，不为单模块擅自替换系统 Qt 或刷机。EGLFS 下 QWidget 仍涉及 CPU 绘制，不凭 GPU 型号保证流畅。

PREEMPT_RT、Qt 事件循环响应和控制 deadline 是不同验收项。QTimer 负载下可迟到，`PreciseTimer` 不是硬实时保证；不默认把 GUI 提为实时优先级、绑核或修改调频。若测量说明必须调整系统，先明确写入范围、受影响配置、必要恢复措施，再按授权执行并复测。
