## 1. 串口、UART 和 TTL 分别是什么

可以先理解为：**让开发板通过几根线，与电脑或其他设备发送和接收数据。** 比如板卡发送 `Hello`，电脑串口终端就显示 `Hello`；电脑发送一条指令，板卡程序收到后作出响应。

| 名称 | 简单解释 |
| --- | --- |
| 串口通信 | 数据按位依次传输的通信方式；本项目主要讨论异步 UART 串口 |
| UART | 通用异步收发器，负责按照设定的速度和格式收发数据；TX 发送，RX 接收 |
| TTL | 原意为晶体管—晶体管逻辑。工程中常用“TTL 串口”称呼直接使用逻辑电平的 UART 接口 |
| USB 转 TTL 模块 | 在电脑 USB 与板卡 UART 信号之间转换，让电脑通过 COM 口收发数据 |

UART 说明数据如何收发，电平规格说明引脚使用什么电压表示 0 和 1。“TTL 串口”不能直接等同于 5V：现代开发板也常使用 CMOS IO，实际电平必须按具体接口资料确认。

UART 通常没有额外的时钟线，双方需要约定一致的波特率和数据格式。波特率表示传输节奏；例如 115200、8N1 表示约 115200 bit/s 的位速率、8 个数据位、无校验、1 个停止位，不等于每秒传输 115200 个字符。[ADI 的 UART 入门说明](https://www.analog.com/en/resources/analog-dialogue/articles/uart-a-hardware-communication-protocol.html)介绍了收发引脚、波特率及帧结构。

## 2. 一般怎么连接

在确认电平兼容、引脚定义正确后，普通无硬件流控的双向连接使用三根线：

```text
开发板                    USB 转 TTL 模块 → USB → 电脑
TX（发送） ─────────────→ RX（接收）
RX（接收） ←───────────── TX（发送）
GND        ────────────── GND
```

这表示双方的发送接对方的接收，并共用地线。开发板使用自己的电源时，模块的 VCC 供电脚不接板卡。接线前先断电并核对电平，不能把 RS-232 接口直接当作 TTL 接口连接。模块上的“3V3”供电脚也不能单独证明其 TX/RX 信号电平。

以上仅说明信号连接关系，不代表本板实物排针的左右顺序。具体位置仍要看丝印和匹配版本的原理图。

## 3. “串口开发”具体做哪些事情

| 工作 | 要做什么 | 完成时看到什么 |
| --- | --- | --- |
| 确认硬件 | 找到目标 UART 的 TX、RX、GND，确认电平及转接模块 | 接口、引脚和电平有明确依据 |
| 检查 Linux 支持 | 确认设备节点、驱动、引脚复用以及是否被控制台占用 | 能确定程序应该打开哪个设备 |
| 配置通信 | 设置一致的波特率、数据位、校验、停止位和流控 | 双方参数一致 |
| 收发与编程 | 先用终端或小程序发送固定文本，再接收并回应 | 两个方向都收到预期内容 |
| 验证与自启动 | 做回环、双向收发和重启复测；按需求增加开机运行 | 结果可复现，有配置和日志 |

Linux 中，串口通常通过 `/dev/` 下的设备节点使用，应用程序打开设备、配置参数，再读写数据。只在目标 UART 没有启用、引脚复用不对或驱动不支持时，才进一步修改设备树或驱动；当前先检查现有系统。

还要区分两种用途：**调试串口**用于启动日志、终端登录等；**业务串口**由程序与外设交换数据。它们可能使用相同类型的 UART 硬件，但占用情况和配置不同，不能未经检查就让业务程序与控制台共用同一路。

业务 UART 可先采用“板卡发送 `Hello UART`，电脑回复 `OK`，应用程序校验收到的内容”作为简单目标；这是后续自定义通信的示例，尚未作为业务程序实施。本次已完成的是控制台交互。

[立创 Ubuntu24 官方教程](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/system-usage/ubuntu24-usage/serial-debug.html)采用 USB 转 TTL 模块和 1500000 波特率。该数值是调试口教程参数，不代表所有 UART 都必须使用同一波特率；接口电平和硬件映射仍应按具体目标确认。

准备时按匹配版本的[原理图](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/open-source-hardware/)核对接口、电平和引脚；板卡版本适用时可参考 [V1.0 的 40Pin 排针说明](https://wiki.lckfb.com/zh-hans/tspi-3-rk3576/hardware-gpio/taishanpi-3m/v1-0.html)。实施时以最新板卡状态和实物资料为准。

### 调试器切换注意

本次已出现：从三针调试口输入检查命令时，连续小写字母 `fiq` 触发 `debug>`，普通 shell 命令未完整输入。Rockchip 驱动对此有特殊处理，尤其不要在该终端粘贴包含相应触发片段的检查命令；可通过 SSH 操作，或换用不包含该序列的筛选表达式。

恢复时在 `debug>` 手动输入 `console` 并回车，看到 `console mode` 后按 Ctrl+C 清除 shell 残留输入。参考 [Rockchip 串口接收处理](https://github.com/rockchip-linux/kernel/blob/develop-6.1/drivers/soc/rockchip/fiq_debugger/rk_fiq_debugger.c)和[调试命令实现](https://github.com/rockchip-linux/kernel/blob/develop-6.1/drivers/soc/rockchip/fiq_debugger/fiq_debugger.c)。
