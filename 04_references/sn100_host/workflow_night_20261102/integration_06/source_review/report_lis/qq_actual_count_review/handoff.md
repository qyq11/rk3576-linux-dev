## 结论先说清

原Windows接收器把首字段当作**本次要读取多少对名称/AD文字**：字段至少够用，再只读前count对，余下尾字段忽略，不是要求整包恰好等于该数量。原循环是`i < count`，没有加1，也没有HIL/Base专门附加规则。

实际7帧均为`Qq[25]`后接`1..24、HIL、Base`共26对。按原接收器，只读前25对`1..24、HIL`，末尾Base不进map。这不等于确认固件“25必定排除Base”的协议规格，也不能说主控坏包；固件为何附带Base仍待协议/实物核对。

Linux原校验要求53字段必须等于`1+25*2=51`，因此整帧被拒。窄修只把“字段数必须相等”改为“声明字段不足才拒绝”，仍只循环前count对，不扩大到26、不按机型或名称特判。
