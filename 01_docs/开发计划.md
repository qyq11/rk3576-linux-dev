## 下一件事：确认并验证目标 TTL 串口

新窗口先阅读根目录 README 和本计划，再开始串口任务。先明确“第八个 TTL”的实际含义，不把 UART8、连接器第 8 针和第八路物理串口直接当成同一个接口。

串口、UART、TTL 的入门说明与连接示意见 [串口 TTL 入门与下一步计划](串口TTL入门与下一步计划.md)。

开始前取得以下信息：

- 板卡硬件版本、对应原理图和目标连接器位置。
- 目标 TX、RX、GND 引脚及 IO 电平，所接 USB-TTL 模块的型号和逻辑电平。
- UART 控制器、引脚复用、Linux 设备节点及当前是否被控制台或其他驱动占用。
- 对端设备、波特率、数据格式、流控及预期输出内容。

接口确认后，先做最小收发验证，需要时再修改设备树、驱动或启动配置。完成后整理为一份串口任务记录，再从 README 链接进入。

## 串口准备要点

- 官方调试串口教程给出侧边三针调试接口、MobaXterm 和 `1500000` 波特率；这一参数不能直接套给所有业务串口。
- 8 数据位、无校验、1 停止位、无流控可作为常规初始方案，实施时对照官方截图和实际需求确认。
- 依据接口标签和原理图确认针序及电平，TX/RX 交叉、GND 共地；板卡使用自己的电源，不把模块的 VCC 当作调试信号连接。
- 供电使用匹配的 5V 电源和板上 Type-C Power 接口；调整接线前断电，串口模块须支持实际所需波特率和电平。
- 开机日志任务要先打开串口终端再上电，保存完整启动过程。官方调试口、业务 UART、网络 ping 中的 TTL 属于不同概念。

## 后续按需求确认的源码工作

原有学习笔记还包含以下方向，保留为后续候选，不自动增加到当前验收任务：

- 获取匹配板卡和内核的 SDK、工具链与官方固件；先做一次不改源码的构建、烧录和启动验证。
- 修改设备树、驱动或根文件系统配置后，重新编译部署，并证明运行系统包含该修改。
- Samba 文件共享；主要属于用户空间服务配置。
- PREEMPT_RT 实时内核；先核对厂商内核分支和匹配支持，再量化测量延迟。

理解源码任务时区分：SDK 是开发套件，IMG 是镜像产物，设备树描述板级硬件，内核管理硬件和运行，根文件系统包含工具与服务。SSH、Samba 和网络管理程序主要在用户空间配置，不因需求名称而直接修改内核。
