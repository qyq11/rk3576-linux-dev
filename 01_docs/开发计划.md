# RK3576 Linux 开发计划

更新：2026-10-21。有线 SSH、侧边三针 TTL 调试控制台及 UART4 回环、重启后复测已通过；后续继续确认扩展需求与外设通信。

完成验收后勾选。已完成事项链接实测记录；未完成事项可先查看入门笔记，实测记录完成后补链接。

## 已完成

- [x] **有线固定 IP 与 Windows SSH**（[实测记录](../02_records/20261021_固定IP地址.md)）

  **完成标准：**重启后保持 `192.168.100.123`，Windows 能 ping、SSH 登录并执行命令。
  **可作判断：**远程操作入口已可用，可以开始串口检查和测试。

- [x] **侧边三针 TTL 调试口基础验证**（[实测记录](../02_records/20261021_TTL串口调试验证.md)）

  **实际结果：**CH340 / COM18，1500000、8N1、无流控；模块回环 3 次共 177 字节收发一致，PowerShell 收到重启日志并完成双向命令交互，MobaXterm 执行 `uname -m` 返回 `aarch64`。
  **可作判断：**串口控制台已可用于板卡操作和排障。本次只验收三针调试口，未验收业务 UART 扩展、业务自启动或长期稳定性。

## 优先推进（按优先级安排）

- [ ] **1. 确认后续目标 TTL 串口**（[入门参考](串口TTL入门与下一步计划.md)，[调试口已验证](../02_records/20261021_TTL串口调试验证.md)）

  **完成标准：**明确“第八个 TTL”的含义，确认板卡版本、TX/RX/GND、电平、UART 编号、Linux 设备节点及占用情况。
  **可作判断：**目标接口在哪里、当前系统是否可直接使用，还是需要调整配置。
  **当前进度：**侧边调试口 `/dev/ttyFIQ0` 已验证；UART4 M0 对应 `/dev/ttyS4`、GPIO2_D0 / GPIO2_D1、40Pin 物理 8 / 10 针，本地回环及重启后复测已通过（[同一份实测记录](../02_records/20261021_TTL串口调试验证.md)）。`/dev/ttyS6` 被蓝牙程序占用，保持原状。“第八个 TTL”的原始含义及外设电平依据仍待明确，本项保留未勾选。

- [x] **2. 完成一路串口双向收发（调试口）**（[实测记录](../02_records/20261021_TTL串口调试验证.md)）

  **完成标准：**通信参数明确，板卡发送的数据由电脑正确接收，电脑发送的数据也由板卡正确接收。
  **可作判断：**本次控制台命令交互链路可用；接入外设或编写业务程序前，仍需确认目标业务 UART 及控制台占用。

- [x] **3. 完成串口回环验证**（[实测记录](../02_records/20261021_TTL串口调试验证.md)）

  **完成标准：**明确回环方式，记录发送量、接收量、内容差异和异常；重启后复测通过。
  **可作判断：**本端收发链路是否通过测试；若异常，可缩小排查范围。回环通过后仍需实际对端验证。
  **实际结果：**用户确认已完成重启复测；截图显示 UART4 `/dev/ttyS4`、115200、8N1、无流控，发送 1600 字节、接收 1600 字节、100/100 条匹配、`PASS`。CH340 模块回环、UART4 接线、程序和重启复测证据统一保存在上述 TTL 串口记录中。

- [ ] **4. 扩展 TTL 串口**（[入门参考](串口TTL入门与下一步计划.md)，实测记录待补）

  **完成标准：**明确所需路数、对端设备及扩展方案；所需串口已引出或启用，每路引脚、电平和 Linux 设备节点对应清楚。
  **可作判断：**现有 UART 资源是否够用，是否需要调整引脚复用或增加外部扩展硬件。

- [ ] **5. 验证扩展 TTL 串口的输出**（[入门参考](串口TTL入门与下一步计划.md)，实测记录待补）

  **完成标准：**各扩展串口按约定参数发送数据，对端正确接收；记录每路发送量、接收量及内容。
  **可作判断：**每路扩展串口的输出是否可用，是否具备向外设发送数据或指令的基础。

- [ ] **6. 验证扩展 TTL 串口的输入**（[入门参考](串口TTL入门与下一步计划.md)，实测记录待补）

  **完成标准：**各扩展串口能正确接收对端发送的数据，接收数量和内容符合预期；有交互要求时能作出约定响应。
  **可作判断：**每路扩展串口的输入是否可用，是否具备读取外设数据并继续做交互程序的基础。

- [ ] **7. 完成开机输出与输入交互**（[入门参考](串口TTL入门与下一步计划.md)，实测记录待补）

  **完成标准：**明确输出属于 Bootloader、内核还是用户程序；所需输出和输入响应在重复启动后可复现，业务自启动以程序手动运行通过为前提。
  **可作判断：**所需功能能否在开机后自动工作，是否可以脱离手工登录运行。
  **当前进度：**三针调试口已接收一次重启日志，进入 shell 后可交互（[记录](../02_records/20261021_TTL串口调试验证.md)）；业务程序自启动与重复启动验收尚未开展。

- [ ] **8. CAN 回环测试**（实测记录待补）

  **完成标准：**确认实际 CAN 接口、波特率及回环类型（控制器内部或外部）；收发帧的 ID、长度和数据一致，记录帧数、错误及重启复测结果。仅软件回显不作为硬件回环通过的依据。
  **可作判断：**所选回环模式覆盖的 CAN 环节是否正常；内部回环通过后，外部总线通信仍需另行验证。

- [ ] **9. Samba 共享文件夹**（实测记录待补）

  **完成标准：**目标电脑能够访问约定的共享文件夹，按预期读写文件；共享端重启后可重新访问。
  **可作判断：**共享文件夹是否可用于日常源码、程序或日志传输。

- [ ] **10. 综合验证并选择后续方向**（实测记录待补）

  **完成标准：**约定对端、TTL 串口路数、CAN 通信要求、速率、响应时间、允许错误、运行时长和重启次数；所需扩展串口同时双向收发通过，相关接口在完整配置下达到约定指标。
  **可作判断：**能否进入业务集成，或需要先补齐 TTL、CAN、扩展、启动或性能方面的能力。

第 3 项串口回环可提前用于第 2 项排查；第 5、6 项在第 4 项完成后分别验收；第 8 项 CAN 回环和第 9 项 Samba 共享文件夹可独立推进，最终统一做第 10 项综合验证。
